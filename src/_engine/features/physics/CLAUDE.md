## Physics

The engine-agnostic Physics API, installed by `physics()` (`PhysicsFeature.ts`, on `aekasha/physics`: the tiers, the tier policy, the physics entities' systems and hooks, the fixed-step driver, its scene hooks, its import extension, the `onUnmount` stop, `initPhysics`). An app that doesn't list it loads no physics module and no Rapier, and `physics.enabled: false` installs it without creating a world at boot. Rapier is the only backend (`backends/Engines.ts`, `ENGINES` keyed by the `PhysicsEngine` union); a settings-driven engine choice (Jolt, Ammo, etc.) is a future extension point, not implemented. The legacy mesh-coupled `PhysicsRapier.ts` has been removed; don't reintroduce a non-ECS physics path. p614 split the three large files; the layout, each module under ~800 lines:

- **The facade:** `PhysicsState.ts` (`facade`, the state the modules share, the getters, `isWorkerTarget`, `assertMainThread`, `assertWorldCreated`; a leaf importing only types), `PhysicsRegistry.ts` (the body, collider and joint maps, the `WORKER_THREAD` collider callbacks, the body-moved listener), `PhysicsStepStats.ts`, `PhysicsQueryStats.ts`, `PhysicsMessaging.ts` (the transport, the requests, the sub-step capture, the pushes, `flushPhysicsEvents`, `toWire*Params`), `PhysicsStepping.ts` (`stepPhysics`, the hold, the step clock and stamps, the gates, the limit, the latch), `PhysicsBodies.ts`, `PhysicsColliders.ts`, `PhysicsJoints.ts`, `PhysicsWorld.ts` (`initPhysics`, the world's life, `stopPhysics`, the snapshots) and `proxies/` (the `WORKER_THREAD` API objects). The imports are a DAG in that order, with one cycle (`PhysicsWorld` ↔ `proxies/WorldProxyAPI`, calls inside functions only). Each create and delete branches once on `isWorkerTarget()`: on `MAIN_THREAD` the async form runs its `*Sync` one.
- **The backend:** `backends/rapier/EngineRapier.ts` is only the `export … from` lines of the contract (`EngineAPIType`, `types/PhysicsBackendTypes.ts`), which `Engines.ts` `import()`s; the code is in `RapierState.ts` (`backend`, the shared state; a leaf), `RapierEvents.ts`, `RapierShapes.ts` (`paramsToShape`), `RapierBodies.ts`, `RapierColliders.ts`, `RapierJoints.ts`, `RapierWorld.ts` (`init`, the world, `step`, the snapshots), `RapierEnums.ts` (the body and shape type conversions) and `proxies/Engine*ProxyAPI.ts`. The API's enums mirror Rapier's: `EngineRapier.test.ts` pins every pair to the installed Rapier's names and numbers.
- **The types** (`types/`, one module per area: common, config, backend, body, collider, joint, query, event, world) and **the protocol** (`protocol/`: `PhysicsProtocolType` with its number ranges per switch, `PhysicsUpProtocol`, `PhysicsDownProtocol` with `PhysicsWorkerReply`, `PhysicsResponses.ts`; all `@internal`). A retired message keeps its number, commented; no other number moves.
- **The rest:** `PhysicsEntity.ts` (ECS integration), `PhysicsInterpolation.ts` (the render interpolation), `ColliderDimensions.ts` (a code-made collider's sizes from its `createGeometry` params), `PhysicsTiers.ts` / `PhysicsTierPolicy.ts` / `PhysicsTierTypes.ts`, the three buffers (`PhysicsTransformBuffer.ts`, `PhysicsDebugStateBuffer.ts`, `PhysicsStepStatsBuffer.ts`), `transport/`, `worker/` (`PhysicsWorker.ts` and the `PhysicsSwitch{World,Rigid,Coll,Joint}.ts` switchboard), `import/` (see Imported physics), `PhysicsUtils.ts` and `PhysicsWallClock.ts` (the deprecated `getPhysGameTime`, removed in engine 6.0.0). The `debug/` modules are p618's.
- Physics objects are ECS components (`BODY_STATIC` / `BODY_DYNAMIC_VISUAL` / `BODY_DYNAMIC_HEADLESS`, synced to `TRANSFORM` every frame at `APP_POST_PHYSICS` by `PhysicsEntity.ts`' `physicsToTransformSystem`). `createPhysicsEntity` is `async` and is the entry point app code should use; it rejects with the backend's error when a body or collider can't be made, and then nothing of it exists (a new entity is deleted, a `target` entity left as it was). A body's create is all or nothing in both targets. Physics objects are still created in code, not yet part of the scene/asset JSON schema.
- Deletes of a stale or unknown id are quiet no-ops (`undefined` / `[]`); a `*Sync` call in `WORKER_THREAD` mode still throws (a misuse). Every export not on `aekasha/physics` is `@internal`.
- Tests: `PhysicsFacade.test.ts` (`MAIN_THREAD`), `PhysicsWorkerRequests.test.ts` (`WORKER_THREAD`: the real worker module and Rapier in Node behind a fake `Worker`, replies can be held), `backends/rapier/EngineRapier.test.ts` (the backend through Rapier's compat build), `transport/PhysicsTransport.test.ts`, `PhysicsTransformBuffer.test.ts`, `import/MeshColliderGeometry.test.ts` (a derivation per shape). `worker/PhysicsWorker.test.ts` bundles the worker and fails on three, `MainLoop`, `Config` or a facade module in it: a type or helper the worker needs goes in a module that imports none of them.

## Worker targets

`AppConfig.physics.workerTarget` (`'MAIN_THREAD' | 'WORKER_THREAD'`, default `'WORKER_THREAD'`) selects where the simulation runs. The API is the same in both; on `WORKER_THREAD` the queries and getters are async, and their `*Sync` twins throw (`throwWorkerSync`) except those the proxy answers from its own copy (`getUserDataSync`, `bodyTypeSync`, `isEnabledSync`, `body1IdSync` / `body2IdSync`, the world's settings and lookups by id; each API type's `@remarks` lists them).

- **The transport** (`transport/`, p614 D5): every message both ways goes through a `PhysicsTransport` (`send` / `onMessage` / `close`, `@internal`; `createWorkerTransport` on the main thread, around the `Worker` from `initWorker`, whose `close()` terminates it; `createWorkerScopeTransport` in the worker, around `self`). Its contract: plain data (no class instances, no functions; rotations go through `toWire*Params`), in order, one message handled to the end before the next. It's the seam p511's network channel implements; nothing else in physics calls `postMessage`.
- **Requests:** the facade keeps its own pending request ids (`messageWorkerAsync`, `messageWorkerAtStep`; `queryWorker` for one field of one object, typed by its message, and `commandWorker` for a one-way command). The worker answers a throw in any switch with `ERROR` and the request's id, which rejects it with `new Error('Physics worker: <message>')`; an `ERROR` without a pending request is logged.
- **The stop** (`stopPhysics`, `@internal`, physics' `onUnmount` hook, run only by `mountAekasha`'s `unmount()`): `MAIN_THREAD` deletes the world; `WORKER_THREAD` closes the transport (the terminate takes the world) and rejects every pending request. Both release the hold, drop the gates and remove the visibility listener. It's for good: `createPhysicsWorld` returns `undefined` after it.
- **The transform buffer** (`PhysicsTransformBuffer.ts`): per-frame rigid-body transforms sync back through a physics-owned buffer, a real `SharedArrayBuffer` when the runtime is cross-origin-isolated (`AppConfig.physics.useSAB`, default `true`; the dev server sends the COOP/COEP headers), otherwise one batched message per frame (`MESSAGE_BATCH`), never one message per body. `maxBodies` (default 2048) sizes it; a full buffer rejects a create with `PhysicsCapacityError`, and `FIXED` bodies take no slot. The buffer keeps each slot's body id, so the worker's write-back walks the used slots (`writeSlotFrom`), and a `MESSAGE_BATCH` push carries only the used slots (`copyUsedBank` / `receiveUsedBank`).
- The `SharedArrayBuffer` is a lock-free triple buffer (p063): the worker writes its back bank, stamps it with its step index and publishes it by an atomic swap with the middle bank, and `MainLoop`'s frame (`runFrame`) calls the fixed-step driver's `latch()` (`latchPhysicsSnapshot()`) right after `timer.update()`, which swaps in the newest published bank. So every reader in a frame (held keys, `APP_PHYSICS_STEP`, the TRANSFORM sync, interpolation, debug wireframes) sees one complete snapshot and its stamp, and a write-back that lands mid-frame waits for the next frame. The fallback uses one bank, since each push is already a private copy.
- The one-way commands `APP_PHYSICS_STEP` systems issue are captured per sub-step (cloned at capture, so reusing scratch vectors is safe; the capture is made on the first command, so a frame without one allocates nothing) and carried in the frame's single STEP message, replayed before their own sub-step.

## Deterministic scene loads

Scene loads are deterministic (p101). Physics' scene hooks (`physicsSceneHooks`, `PhysicsFeature.ts`) hold physics stepping for the whole load (`holdPhysicsStepping`, `loadStart`), replace the physics world with a fresh one (`resetPhysicsWorld`, `beforeAssets`: right after `createCameras`), and release the hold only after every `createPhysicsEntity` call has finished (`settlePendingPhysicsEntities`, `entered`, which also catches un-awaited ones; released again in `loadSettled`). So a scene simulates identically on every visit, in both worker targets. The rules this puts on simulation code are the root's (Physics); in addition:

- An entity deleted while its `WORKER_THREAD` create is in flight (a scene exit) gets nothing: what the create made is deleted again, and the promise resolves with the dead id.
- The snapshot functions (`takePhysicsSnapshot` / `restorePhysicsSnapshot`, `PhysicsWorld.ts` / `RapierWorld.ts`) are p500's, moved as they were.

To check determinism, append `?physicsProbe=N` (debug mode) or use "Determinism probe" in the Physics API debug tab. It freezes physics N fixed steps after each scene enter, logs a hash of every dynamic body's state, and diffs it against the last run of the same scene and N. The probe leaves characters out of its hash; the scene runner hashes their paths instead. The gym's `ARE_CHARACTERS_ENABLED` flag leaves its characters out. `yarn verify:scenes` probes every scene in all three targets this way (steps and known non-deterministic scenes in `devTools/verify/scenes.config.ts`: `unstableHash`), and on `MAIN_THREAD` compares every character's path per step (`getCharacterPaths`), driven by a scene's input script (`inputScript`, the gym's in `devTools/verify/inputs/`; `devTools/verify/CLAUDE.md`).

## Simulation tiers

Simulation tiers (`_DONE_p352`, `PhysicsTiers.ts`): a `DYNAMIC` `createPhysicsEntity` body (not a character, p420 owns those) can be `FULL`, `STATIC` (made `FIXED`), `DISABLED` (`setEnabled(false)`) or `REMOVED` (detached from the Rapier world with its ids, proxies and state kept engine side, `detachRigidBody` / `reattachRigidBody`; its transform-buffer slot is freed). `requestPhysicsTier` applies at the next `APP_PHYSICS_STEP` sub-step (`physicsTierSystem`, order 100); jointed bodies change tier as a group and can't be `REMOVED` (`isBodyJointed`, `PhysicsJoints.ts`). `STATIC` / `DISABLED` entities sit in `BODY_STATIC`; a `REMOVED` one has no bucket or `COLLIDER` component (so `world.getRigidBody` is undefined; the body lives on `PHYSICS_SIM_TIER.body`, and `getPhysicsEntityBody` reads it either way). Fixed bodies take no slot and `BODY_STATIC` isn't synced per frame: a moved one reaches its transform through `setBodyMovedListener` and `queueStaticBodySync`. Joint checks read the facade's joint registry, which `createJoint` (`PhysicsJoints.ts`) fills but `getPhysicsWorld().createJoint` on `MAIN_THREAD` bypasses.

- The distance policy (`PhysicsTierPolicy.ts`, `setPhysicsTierPolicy`; members via `createPhysicsEntity`'s `tierPolicy` option) runs with `cadence: 'STEPS'` by default (`_DONE_p343`): an `APP_PHYSICS_STEP` system (order 110) measures member and focus positions on steps that are multiples of `interval` (`readBodyPositionsAtStep`) and decides `interval` steps later; in `WORKER_THREAD` mode it holds stepping with `addPhysicsStepGate` until the reply arrives. A pass allocates nothing but that request: its measurements are pooled, and a late reply to an earlier use of one is ignored (its `use` counter). The focus defaults to the main camera (`getMainCamera()` for the default world). `'FRAMES'` runs at `APP_LOGIC` from `TRANSFORM`s and isn't deterministic; the probe freezes only that cadence. Freeze sources are per world (`setPhysicsTierPolicyFrozen(frozen, source)`, `@internal` like the policy's other debug reads).
- `getPhysicsSubStepIndex()` is the step clock for `APP_PHYSICS_STEP` systems (-1 outside a sub-step), and `addPhysicsStepGate(step)` is the production way to make stepping wait for something; the debug-only `setPhysicsStepLimit` is separate. A new world drops every gate.
- The `physicsTiers` scene is the demo and the verification scene: with its policy running, the probe hash is the same on every load and in all three targets (`MAIN_THREAD`, `WORKER_THREAD` with and without SAB).
- p622 holds the tiers as a feature of their own (`physicsTiers()`, engine 6.0.0); until then `physics()` installs them.

## Imported physics

`spawnImportedAsset` (`kernel/assets/import/SpawnImported.ts`) gives glTF nodes physics from their custom props (glTF `extras`, parsed by the kernel's `CustomProps.ts`: `isPhysObj`, `colliderType`, `keepMesh`, `rigidType`, `index`, the shape sizes, `density` / `friction` / `restitution` defaulting to 0.2, `userData_<key>`), which its `physicsParams` override per node. The spawn is physics' import extension (`spawnPhysics`, `registerImportExtension`), whose code (`import/ImportPhysics.ts`, `spawnImportedPhysics`) and the derivation load on the first spawn with physics nodes.

- One rigid body per `index` group, carried by the group's node with a `rigidType`, and a collider per physics node of the group; the nodes without an `index` form one group together. The body attaches to a mesh entity (the anchor: the body's node when visible, else the group's first visible node), the other colliders offset from it; a group without a visible node is a headless physics entity.
- The derivation (`import/MeshColliderGeometry.ts`' `deriveColliderFromGeometry`, p614 D13): TRIMESH / CONVEXHULL / HEIGHTFIELD shape data from the node's geometry × scale (a HEIGHTFIELD that isn't a whole grid, or under 1 × 1 cells, is skipped with an error naming the import and node), and a primitive's missing sizes from `import/ColliderBounds.ts`' `getColliderBounds` (the geometry's bounds × the node's scale, under `ColliderParams`' names). A capsule, cone or cylinder stands on Y; a `spineAxis` custom prop of `x` or `z` (either case) gives it an `orientation`, which the backend composes with the collider's `rotation`. Every primitive is centred on its node's origin. A field the params set is never overridden, and the registered geometry never changed.
- Quantized positions break CONVEXHULL and HEIGHTFIELD: the asset pipeline keeps a GLB with a `colliderType` node lossless (`docs/techniques/asset-optimization.md`).
