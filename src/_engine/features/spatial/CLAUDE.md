Notes for the spatial index (`src/_engine/features/spatial/`); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Spatial index

`features/spatial/SpatialGrid.ts` is the grid (sparse CSR cells, an oversized tier, zero-allocation queries that return candidates, not results; a `queryVisit` visitor returns `true` to stop, as light culling does at its first receiver); `CellKey.ts` holds the cell maths every cell-keyed structure shares; `SpatialDomains.ts` is the domain registry (settings, scene scope, the debug override and stats) and `SpatialIndexSystem.ts` the ECS wiring (membership, radius providers, the rebuild system; `_DONE_p050`, `_DONE_p346`, `_DONE_p349`), with the debug-only brute-force oracle in `SpatialOracle.ts` (it checks light culling's queries, and a consumer's own after `validateSpatialGridQuery`, on `aekasha/spatial`). The `spatial()` feature (`SpatialFeature.ts`, on `aekasha/spatial`, p607) installs it and light culling (`LightObjectCullingSystem.ts`); without it nothing is indexed.

- Each world holds named domains (`registerSpatialDomain(world, { id, cellSize, maxMembers, update })`), each its own grid. Read a grid with `getSpatialDomain` / `getSpatialGrid` where it's used: re-registering with other settings replaces it. Its membership is `SPATIAL_INDEXED` (the `spatialIndex` entity flag, on by default for meshes and point/spot lights), and light object culling queries it. Other domains use `joinSpatialDomain` / `leaveSpatialDomain` (a `SPATIAL_DOMAINS` bit mask, at most 31 per world besides `DEFAULT`); a full one refuses with a dev warning. `unregisterSpatialDomain` removes one (not `DEFAULT`): every member leaves it and its bit is reused. `InstancedMeshPool`'s `spatialDomain` option joins its instances through the membership `spatial()` sets in `kernel/ecs/SpatialMembership.ts` (without `spatial()` it warns once per spawn). Instances in `DEFAULT` are never light receivers: light culling's receiver test reads the mesh's `OBJECT3D`, which an instance hasn't (`docs/issues/pool-instances-not-light-receivers.md`), so give a pool a domain of its own (largeWorld's `FOLIAGE`).
- Scene scope: a registration with `sceneId` is that scene's settings, which win over the domain's world settings (the last registration without one) until the scene exits. Then the domain goes back to its world settings, or is unregistered if it has none; a persistent member of an unregistered domain leaves it. A scene's JSON can list its own (`spatialDomains`: `DEFAULT` takes a partial entry merged over its world settings, other domains need `cellSize` and `maxMembers`). The `spatial()` feature's `worldCleared` scene hook (`SpatialFeature.ts`) calls `releaseSceneSpatialDomains` right after `clearNonPersistent()` (so a revert re-inserts only persistent members), then `registerSceneSpatialDomains` for the next scene's JSON, before anything of it joins a domain.
- `DEFAULT`'s grid is per scene: built on demand (by its first `SPATIAL_INDEXED` member, a `getSpatialGrid` call, or the rebuild system when persistent holders are left), at the settings in effect then (cell size 20 and `world.maxEntities` members unless registered otherwise), and freed on every scene change. Its settings outlive the grid: registering `DEFAULT` without a grid only stores them. So `getSpatialDomain(world, 'DEFAULT')` can be undefined; light culling reads it that way, so it never builds a grid.
- Update policies: `DYNAMIC` refreshes positions and rebuilds every frame; `STATIC` rebuilds only in a frame where a member joined or left; `MANUAL` only on `rebuildSpatialDomain`. `invalidateSpatialDomain` refreshes and rebuilds any domain at the next frame (a `STATIC` domain whose members moved). The rebuild runs at `APP_POST_PHYSICS`, order -1. A leave is seen at once (the grid patches the cells it touches); a join or a move only after the next rebuild, so a `MANUAL` owner rebuilds before it queries. A `DYNAMIC` domain pays the refresh and the rebuild every frame, moved or not (about 0.2 µs per member: `docs/issues/spatial-refresh-and-rebuild-cost.md`), so a large domain that rarely moves is `STATIC` and invalidated (largeWorld's `FOLIAGE`).
- Radii come from providers (`registerSpatialRadiusProvider(componentType, fn, { scaleIndependent? })`, a kernel registry in `kernel/ecs/SpatialMembership.ts`, p607, so another feature registers without importing the index): meshes and pool instances return their geometry's `|center| + radius`, scaled by the Transform on every refresh; lights their range. `refreshSpatialRadius(entityId)` re-reads one after what its provider measures changed.
- The "Spatial index" debug tab (`features/spatial/debug/_dbg__SpatialGrid.ts`, default world only) works per domain: cell size override (saved for the scope it was edited in: the world settings or one scene's), brute-force oracle, overlays, rebuild counts and an all-domains summary.
