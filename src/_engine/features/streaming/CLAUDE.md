Notes for world streaming (`src/_engine/features/streaming/`, `aekasha/streaming`: the cells, their state machine and content, and the Streaming debug tab); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Streaming

The `streaming()` feature (`StreamingFeature.ts`, p353, docs/plans/p353_macro-streaming-grid.md): a scene larger than what fits in memory at once, cut into square cells on x/z whose content loads and unloads by its distance to a focus. Phases 1-2 are in: cells, the state machine, code-registered content and asset ownership per cell; priming (Phase 2's last section), far representations, the build-time manifest and per-cell physics tiers are later.

- **Settings.** A scene opts in with `streaming: { cellSize, rings?, margin? }` in its JSON (`StreamingSchema.ts`' `streamingSchemaPart`, so the feature manifest names `streaming`) or `setSceneStreamingSettings(sceneId, settings)` (over the JSON's; `null` off, `undefined` back to the JSON's; read at the scene's `created` hook, so from its scene code works). `cellSize` is a power of two of at least 32 m (p306's blocks tile it); `rings` each state's outermost ring in cells (Chebyshev from the focus cell), `resident` 1, `nearby` 2, `far` 5 by default, `resident <= nearby <= far`; `margin` defaults to `cellSize / 4`. The checks are `StreamingSettings.ts`' (no zod: the runtime and the schema's refine share them, and a build ships no schema). The budgets are `AppConfig.streaming` (`updateIntervalFrames` 10, `maxConcurrentLoads` 2, `maxCreateMsPerFrame` 2), read at the install.
- **The cell maths** is `src/_engine/utils/CellKey.ts` (moved out of `spatial()` in Phase 1: a feature imports no other feature's code); a cell key is `packCellKey(cx, 0, cz)`, made by `getStreamingCellKey(cx, cz)` / `getStreamingCellKeyAt(x, z, cellSize)` (which throw outside the key's range).
- **Levels** (`StreamingRings.ts`, pure): `RESIDENT`, `NEARBY`, `FAR`, `UNLOADED`. `decideStreamingLevel` promotes a cell to the nearest level whose ring holds it and demotes it only once the focus is more than `rings[level] × cellSize + margin` from its edge (`getCellEdgeDistance`, Chebyshev in metres), to the nearest level that still keeps it: a focus on a boundary never thrashes. `DEEPEST_LOADED_LEVEL` is `NEARBY` until Phase 5's far representations, so a `FAR` cell has no content yet.
- **The machine** (`StreamingCells.ts`, no engine state; its tests drive it with their own clock): per cell `UNLOADED → LOADING → LOADED(level) → UNLOADING → UNLOADED`, with a generation counter bumped by every load start, cancel and drop. `decideStreamingCells` (every `updateIntervalFrames`) moves the tracked cells and starts tracking the untracked ones within the loaded rings, nearest first; `pumpStreamingCells` (every frame) starts loads up to `maxConcurrentLoads`, runs their content units nearest first and unloads farthest first, the two sharing `maxCreateMsPerFrame`, checked before each unit (a frame always runs one of each, and can go over by one unit). A load no longer wanted is cancelled: its units not started are skipped, what's done unloads, and an async unit that comes back late (a stale generation) is unloaded at once (`lateResults`). A cell wanted again while it unloads finishes the unload, then loads again. A unit whose `load` throws, rejects or returns no id array is logged and counted (`unitErrors`), and the cell still loads. `setStreamingTransitionListener` (one listener, `@internal`) is the debug tab's cell history: the machine pays a null check.
- **Content** (`StreamingContent.ts`): `registerStreamingCellContent({ sceneId, cellKey, load, unload? })` (`Streaming.ts`, with the install check) adds a unit; `load(ctx)` returns the ids of the entities it made (or a promise of them), `unload(ids, ctx)` takes them down (default: deletes them). `ctx` (`StreamingCellContext`) has the cell, the world and `isCurrent()` (false once the load is cancelled or the scene left: checked after every `await`). A unit is the slice a frame can't split, so a big cell is many units. A scene's registrations go on its exit, so its scene code registers them on every load (before its cells load); a cell already loaded takes a new unit on its next load. `unregisterStreamingCellContent` takes the same object.
- **Asset ownership** (p353 §4.2; the kernel side is `src/_engine/kernel/scene/CLAUDE.md`'s Asset ownership): a cell's owner key is `sceneId#cellKey` (`cell.ownerKey`). Each unit's `load` runs in it (`runInAssetOwnerScope`) up to its first `await`, an asset load it starts there registers in it after its own awaits, and `ctx.runOwned(fn)` puts code after an `await` in it. Once a cell's unload is done, `finishUnload` calls the runtime's `releaseCellAssets` (`releaseCellOwnedAssets`): what the cell alone held and nothing uses is freed (`assetReleases`, `assetsReleased`). A cancelled load's async units still out hold it back (`cell.lateUnits`, counted at the cancel; the last one to settle releases), and so does another cell object tracking the key (a load of it may be running): its own unload releases. The scene's exit releases nothing (`isDropped`): SceneLoader's `releaseSceneOwnedAssets` takes the cells' keys with the scene's, and when the same scene loads again (SceneLoader releases nothing then), `created` releases the dropped cells the new load didn't load again (`droppedCells`). A release scans every registry (3-5 µs at `streamingGrid`'s 17 assets, linear in the assets registered). Mesh entities' ref counts free most of a code unit's assets anyway (a mesh's geometry and material on their last ref, the material's textures with it): the release is for what no entity holds, a texture a cancelled unit loaded before bailing out, an import's record and unused geometries, and Phase 3's JSON assets.
- **Runtime** (`Streaming.ts`): `streamingSystem` (default world, `MAIN`) decides and pumps the current scene's machine, never during a load (`loadStart` → `loadSettled`). The scene hooks: `sceneRegistered` keeps the JSON settings, `exit` drops every cell (their unloads run, in reverse install order before physics' entities) and the scene's registrations, `created` builds the machine and loads the cells around the focus at once, with no budget, awaited, so they're part of the load (inside physics' hold, p101). The focus (`setStreamingFocus`: an entity's `TRANSFORM` position or a point read at every decision; `null`, the default, the main camera) lasts across loads; while its entity doesn't exist the cells keep their states. `getStreamingCellState(cellKey)` reads a cell's state in the current scene.
- **Debug** (`debug/`, registered with `if (IS_DEBUG_ENV) ctx.onDebug(registerStreamingDebugGUI)`): the Streaming tab (`_dbg__Streaming.ts`, `streamingControls`, after LOD in `DEFAULT_DEBUG_DRAWER_TAB_ORDER`, icon `streaming`; nothing persisted): the scene's settings, the focus and its cell, the cells per state, the machine's counters, Freeze focus and Teleport focus to cell (the focus override, `setStreamingFocusOverride`, over the app's focus while set), the budgets live, the overlay and a row per tracked cell (its GPU bytes in the subtitle) opening its window (`_dbg__StreamingCellWindow.ts`, a window kind removed on a scene change: the cell's state, ring, load time, units, entities, GPU memory, the assets its owner key is on, and last 12 transitions). The bytes and assets are `_dbg__StreamingMemory.ts`' (the GPU memory tab's `collectGPUAssets`: an asset several cells share counts under the scene), read once per refresh. The overlay (`_dbg__StreamingOverlay.ts`) draws the tracked cells' outlines at a set height, a line per state colour (an empty line hidden), and the focus as a cross; without `lines()` it's off with one log line. `?streamingFocus=x,z` sets the override before the first load (read in the install, only in the debug env and prod test mode).
- **Not yet** (later phases of p353): the determinism probe doesn't freeze the focus (Phase 4 adds the kernel seam it needs; Phase 1's content has no physics), nothing is primed, and the tab has no priming or upload rows.
- The test scene is the app's `streamingGrid` (`src/app/scenes/streamingGrid/`): 16 × 16 cells of 64 m, each a terrain block (its own geometry, the cell's asset) and two units of scattered props on one world-space height field; the main camera flies across the grid, hovers on a cell boundary or stays (its scene tab). p353 Phase 1's measurements are in the plan.
