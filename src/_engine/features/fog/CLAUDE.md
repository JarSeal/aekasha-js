Notes for the fog (`src/_engine/features/fog/`, the `fog()` feature on `aekasha/fog`, p106; the sky's horizon colour it follows is the sky box's, `src/_engine/features/skybox/CLAUDE.md`); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Fog

One fog per scene (p106 D1-D7 and Phases 1-5's As built): `LINEAR` (three's `Fog`), `EXP2` (three's `FogExp2`) or `HEIGHT` (an analytic exponential height fog), its colour the sky's horizon by default, with a sun glow in every mode, as the root scene's `fogNode`. No raymarched or froxel fog, and no light shafts: the plan's "Why not" and Phase 6 (three's `godrays` doesn't compile under VSM and its depth pre-pass is most of its cost; the idea is in p990's Rendering).

- **Where the parts are.** `FogTypes.ts`: `FogDef` (every key filled in) and its parts. `FogSchema.ts`: `FogAssetSchema` (strict: an unknown key fails; `linear.far` must be past `near`), `FogOverridesSchema` (a scene's save entry) and `fogSchemaPart` (the scene's `fogs`, feature `'fog'`). `FogDefaults.ts`: `FOG_DEFAULTS`, `resolveFogDef` (the defaults filled in, `sunScattering.enabled` from the mode: on for `HEIGHT` only) and `applyFogSaveEntry` (a deep merge), out of the schema's module: **the runtime imports only types from `FogSchema.ts`**, since a value import keeps its zod schemas, and zod with them, in the first download (21 KiB gzip, Phase 7's SBP run). Both on `aekasha/schemas`. `FogNode.ts`: `createFogNodes` (the uniforms and the graph) and the factors' CPU twins (`getLinearFogFactor`, `getExp2FogFactor`, `getHeightFogFactor`, `getFogSunGlow`). `FogTransitions.ts`: `updateFog`'s channels as plain arrays (no three, no ECS; the `SurfaceConditionsModel.ts` pattern). `Fog.ts`: the running state (made at the install, null before), `fogSystem`, the scene hooks' bodies and the API. `FogFeature.ts`: `fog()`, id `fog`, and `fogSceneHooks`. `debug/`: the tab (Fog debugging).
- **Without the feature** the getters (`getFog`, `getFogNodes`, `isFogEnabled`) return null, the setters throw naming the factory, and a scene listing `fogs` fails the boot (`checkSceneFeatures`).
- **The data** (D2): a `<id>.fog.json` (`GATHERED_SUFFIXES`' `fog`; `withIdDefault` gives it its file's name as its id) or an inline definition (its `id` required) in a scene's `fogs` list, like `skyboxes`. The scene starts with the last one with `isDefault`, else the first. The gather resolves each (`resolveFogDef`, so a save entry that changes the mode keeps the glow as it was), deep merges the scene's `__saveData` entry over it, drops `debugData` in production and fails on an id twice in a scene's list (`devTools/gather/CLAUDE.md`). The development data's `fogs` section (each file's fog with its `__sourcePath`) is what the save finds a file by; `__inlineAssets.fogs` names a scene's inline ones. A fog one scene uses sits in its folder, a shared one in `src/app/fogs/`.
- **One graph, never recompiled** (D3). three r187 keys every draw on the fog node's cache key, so a different `scene.fogNode` recompiles every material in the scene. `createFogNodes` builds one graph over uniforms made once a page load (`getFogNodes()`; none at module load): the three factors, each × a one-hot `modeWeights` component (x `LINEAR`, y `EXP2`, z `HEIGHT`), × `enabled`, into three's `fog(glowColor, factor)`. Switching the mode, the glow, a fog or the master switch writes uniforms only. `FogNodes` holds `node`, `factor` (public: the factor alone, a float node) and each uniform. **Every uniform is in three's `renderGroup`** (shared, written once per render call), as three's own `scene.fog` uniforms are: three refreshes a classic material's (`MeshStandardMaterial`, the engine's `STANDARD`) per-object uniforms only when the material, the object or the lights change (`NodeMaterialObserver.needsRefresh`), so in the default group those draws kept their first frame's fog (Phase 5's bug, `FogNode.test.ts` checks the group). Any scene-wide uniform a classic material reads has the same trap.
- **`HEIGHT`** (D4): the density `density · exp(−falloff · (y − baseHeight))` integrated along the camera-to-fragment ray in world space (`cameraWorldMatrix × (positionView, 0)`, right for sprites, fat lines and vertex nodes), from `startDistance` on, as `1 − exp(−density · fogLength · meanDensity)`, at most `maxOpacity`; `meanDensity = (ρ_start − ρ_end) / (falloff · Δy)`, the midpoint below `FOG_FLAT_RAY_EPSILON` (1e-3), each end's exponent at most `FOG_MAX_DENSITY_EXPONENT` (60: a camera deep below `baseHeight` gets full fog, not an overflow), a ray at least `FOG_MIN_RAY_LENGTH` (1 µm). Its length is the Euclidean one where `LINEAR` and `EXP2` keep three's view depth (`rangeFogFactor`, `densityFogFactor`), so it's a little thicker toward the screen's edges. three's `exponentialHeightFogFactor` isn't this integral. **Trap:** `@types/three` still declares `rangeFog` and `densityFog`, which r187's JS doesn't export: importing either fails the build.
- **The sun glow** (`sunScattering`, every mode): `mix(color, sunColor, sunStrength · max(dot(rayDir, sunDirection), 0)^sunExponent)`. It changes the colour, not the factor. `sunDirection` zero is no sun (no glow; what it starts with), `sunStrength` 0 while the fog's glow is off, `sunExponent` at least 1e-3 (`pow(0, 0)` is undefined in WGSL).
- **The uniforms' writes** (`Fog.ts`): `computeTargets` turns the fog into the channels' targets, kept drawable (no negative distance or density, `far` at least `near` + 1 mm, the opacity and the glow's strength in [0, 1]); `writeNodes` writes the switch and the mode at once on a change, `writeChannels` the numbers, `writeSources` the colour and the sun. Nothing allocates.
- **`fogSystem`** (`MAIN`, order 1, default world only; registered at the install through `ctx.registerPlugin`): after `skyBoxSystem` by install order (the template lists `fog()` right after `rainOcclusion()`), so the sources read this frame's sky. Each frame: the transitions (not while a scene loads), the sources, the background.
- **The sources** (D5, `setFogColorSource((out) => boolean)`, `setFogSunSource((direction, color) => boolean)`; set once, kept across scenes, read on every change and every frame, so an `updateFog` from a later stage never renders the fallback colour for a frame): each writes a scratch copied into the uniforms only on true. Under `colorSource: 'SKY'` the colour is the source's, else the colour channels' (`MANUAL`, and `SKY`'s fallback); the sun source is read in every mode. The template's `appECSPlugins` wires both (Phase 3, decided at its review): the colour `getSkyHorizonColor(out)` (the horizon away from the sun), the glow `getSunDirection` with the sky's horizon toward the sun as its colour (not the light's colour × intensity: that outshines the sky). Phase 3 measured the CPU colour against the rendered horizon through the `DAY_NIGHT` cycle: equal within float precision away from the sun, dusk included.
- **Transitions** (`updateFog(values, { transitionSec? })`, `FogTransitions.ts`): one channel per number the uniforms take (the colour's linear r, g, b, every mode's parameters, the glow's strength and exponent). A call moves only the channels whose target changed, from where they are, the others keep running (the latest call wins per value); the far is kept past the near at the write, since they can move on different clocks. Switching the glow's `enabled` fades its strength; `mode`, `enabled`, `colorSource` and `background` switch at once. `getFog()` returns the new values at once (a new object: the scene's data is never changed). Non-finite numbers are ignored. The clock is `getElapsedTime()`'s change (the master loop's: it stops with its pause and an editor view, scales with the play speed, not with the app pause alone), standing still while a scene loads. `setFog` and a scene's exit end every transition at its target. `onFogChange` hears `'update'` once a call.
- **The scenes** (`fogSceneHooks`): `worldCleared` takes the next scene's `fogs`, shows its default (with the debug overrides, debug env only) and puts the graph on the root scene before its scene code and materials build. `exit` clears the fog, the scene's fogs, the graph off the root scene and the background back. **The graph stays on the root scene until the exit** (D3 said null without a fog): `setFog(null)` and switching fogs write `enabled` and the weights only. A scene without `fogs` has no fog node and pays nothing; its first `setFog(definition)` recompiles each material once.
- **The master switch** (`setFogEnabled`, `isFogEnabled`): kept across scenes, × the fog's own `enabled` into the `enabled` uniform.
- **`background: 'FOG_COLOR'`** (`syncBackground`): while the fog renders and the root scene has no `backgroundNode` and no texture background, its background is a `Color` the fog writes in place (over the scene's own `backgroundColor` too); what was there comes back when it lets go and at the exit.
- **`onFogChange`'s reasons:** `'set'` (another fog, or a scene's at its load), `'update'`, `'enabled'`, `'clear'` (lowercase, as `onSkyBoxChange`'s).
- **What it fogs** (D7): the root scene only. Viewports' scenes, the env ball and the axes gizmo (their own scenes), snapshots' and bakes' scenes get no fog node; a viewport takes `getFogNodes().node` itself (the JSDoc's recipe). The background is never fogged (three's `Background.js`), nor shadow, bake, impostor-bake, static sky layer and rain occlusion materials (`fog = false`). A material's own `outputNode` replaces the fogged colour; a `fragmentNode` is fogged. Impostors are fogged at the billboard's depth. PostFX AO runs after the fog and darkens fogged distance. Debug helpers: `markDebugHelper` sets `fog = false` (Fog debugging).
- **Size:** the feature's modules are in the app's first download (the `_engine/features/fog` group in `sbp.config.ts`, budget 3 KiB), the tab a debug chunk; the banner has none (`FEATURE_GROUPS`).
- **Gameplay:** the fog is visual and runs at frame time: no simulation lint, not saved with a game (p427's weather state, which sets it through `updateFog`, is).
- **Tests:** `FogDefaults.test.ts` (the defaults, the save entry's merge), `FogSchema.test.ts` (the refusals), `FogNode.test.ts` (the node is the same object across a mode switch and a toggle, the uniforms' group, the twins: `HEIGHT` against a numeric integral up and down, across the epsilon, `startDistance`, `maxOpacity`, the extremes), `FogTransitions.test.ts`, `Fog.test.ts` (the API, the scene reset, the sources, the debug hooks), `gather.test.ts` (an id, inline, `__saveData` merged, the development data's `fogs`). The graph compiles only on a GPU: `fogShowcase` (`src/app/scenes/fogShowcase/`, its scene runner variants `@linear`, `@exp2`, `@height`) is its verification scene.

## Fog debugging

The debug drawer's Fog tab (p106 D8, Phase 4's As built), loaded by `fog()`'s `ctx.onDebug` inside `if (IS_DEBUG_ENV)`, so a production build has none of it.

- **The tab** (`debug/_dbg__Fog.ts`, `fogControls` after `surfaceConditionsControls` in `DEFAULT_DEBUG_DRAWER_TAB_ORDER`, its icon the built-in `fog`, `aekasha/ui`'s `fogIcon`; `keepOnSceneChange`, every field a `{ get, set }` over the live fog, refreshed every 250 ms and on `onFogChange`): "Scene's fogs" (a select of the scene's fogs, a code fog while it shows and none: `setFog`, undoable as `fog.select`; the master switch; a note for no fog or a code fog), "Fog" (its `enabled`, the mode as a segmented control, only the mode's fields shown), "Colour" (the source; under `SKY` the sky's live colour as text, or that the fog falls back, and the colour field as "Fallback colour"; under `MANUAL` "Colour"; switching to `MANUAL` while the sky's colour shows seeds the colour from it, one undo step with the source; the background), "Sun glow" (its fields and the sun's colour as text), "View" (the fog factor switch) and Copy JSON (the definition as `getFog()` has it). Its header clears the tab's UI state (`AEK_debugFogUI`) and the overrides. The master switch and the view are runtime only (no undo, no save), like the sky box's day-night transport.
- **Edits** (`debug/_dbg__FogEdits.ts`): a field's write goes through `updateFog` (at once) and into `AEK_debugFog` (`FOG_DEBUG_OVERRIDES_LS_KEY`, `{ [sceneId]: { [fogId]: FogOverrides } }`), pruned against the scene's definition (only what differs is kept), recorded as `fog.values` (`{ sceneId, fogId, prev, next }` as partial definitions; a drag's ticks coalesce by path). An undo for another scene than the current one waits for it. A fog made in code shows its edits but keeps none.
- **The overrides in the runtime** (the sky box's way): `Fog.ts` merges a scene fog's overrides in (`withDebugOverrides`, `applyFogSaveEntry`) when it shows, at a scene's start and on `setFog(id)`, only in the debug env, so a production build never reads LS. The tab's `@internal` hooks: `_getSceneFogs` (the scene's id and fogs without the edits), `_setFogViewNode` / `_getFogViewNode`, `_isFogSkyColorLive` (whether `writeSources` took the sky's colour this frame).
- **The save source** (`debug/_dbg__FogSave.ts`, id `fog`, the sky box's way; registered when the tab is made): the Æ menu's Save writes each scene's latest entry with the overrides deep-merged, pruned against the file, into the `.fog.json`'s `__saveData` (`findSceneAssetFile({ list: 'fogs', registry: 'fogs' }, …)`), then drops those overrides. An inline fog moves into `<scene folder>/<id>.fog.json` (`_dbg__SaveEntries.ts`' `fogs` kind, `INLINE_FILE_TYPES`, `INLINE_FILE_SCHEMAS`).
- **The fog factor view:** `vec4(vec3(factor), output.a)` shown in the graph's place by `_setFogViewNode` (`showFogNode` takes it over the graph; a scene's exit takes either off), kept across scenes until switched off. A different fog node, so switching it recompiles every material: fine in the debugger.
- **Debug helpers aren't fogged:** `markDebugHelper` (`src/_engine/debug/CLAUDE.md`) sets `fog = false` on the subtree's materials as they are at the call: the 3D symbols (marked after their per-clone materials), the light and camera helpers, the ray helpers, the physics wireframes, the character gizmos, the Debug tools' grid, axes and polar grid, and the lines overlays (LOD, spatial, merging, streaming, world bounds).
- **The showcase's tab** (`src/app/scenes/fogShowcase/_dbg__fogShowcase.ts`, scene-scoped): the fog switch (`setFog`), the day (hour, play, speed) and "Fill the valley" / "Lift it" (`updateFog` over 4 s). Runtime only.
- **Tests:** `_dbg__FogEdits.test.ts`, `_dbg__FogSave.test.ts`; Phase 5 checked the path in a browser (an edit kept across a reload, undone, saved into the file, loaded from it).
