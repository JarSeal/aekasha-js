Notes for the text feature (`features/text/`, `aekasha/text`): the font asset, its layout format and the fonts' runtime load (p391; p392 adds the texts, their layout and the MTSDF graph); the encoder is `devTools/assetPipeline/CLAUDE.md`'s, the gather's part `devTools/gather/CLAUDE.md`'s, the how-to `docs/techniques/text-fonts.md`; the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Font assets

- **The asset** (`FontSchema.ts`, on `aekasha/schemas`; p391 D2): a `*.font.json` beside a static TTF, OTF or WOFF (`fileName`, JSON-relative; `.woff2` refused by the schema, a variable font or a collection by the encoder, each naming what to use). `FONT_TYPES` (`MTSDF`, the default: the median in RGB and the true SDF in A; `MSDF`, A 255; `SDF`, a one-channel `R8_UNORM` atlas), `FONT_CHARSET_PRESETS`, `FONT_DEFAULTS` (the encoder fills them in: `size` 48, `pxRange` 8, `fallbackGlyph` `?`, `kerning`, `atlas` 2048 / 2 / pot). `id` optional (the file name), `size` 8-512, `pxRange` > 0, ≤ 64 and below `size`, `atlas.maxSize` a power of two 64-8192, `padding` 0-32, `fallbackGlyph` one code point. A font without `charset` gets `ASCII`; a `charset` without `presets` none. No `__saveData`, `debugData` or `optimize`. Tests: `FontSchema.test.ts`.
- **The presets' characters** (`FontCharsets.ts`, `getFontCharsetPresetCodePoints`, `isControlCodePoint`): import-free, on `devTools/engineImports.test.ts`' list, since the encoder (`devTools/assetPipeline/fonts/charset.ts`) and `yarn importFont`'s coverage read them; the debug tab's "what's in this font" (p392) will too. A control character is never a glyph.
- **The scene field** (`TextSchema.ts`, `textSchemaPart`, feature id `text`, last in `devTools/gather/engineSchemas.ts`' `ENGINE_SCHEMA_PARTS`): `fonts`, font ids. A scene listing one gets `text` in its manifest, so `InitEngine` requires `text()`. p392 adds `texts` to the same part.
- **The generated entry** (`SceneFontDef`, `FontSchema.ts`): `{ id, type, __url?, __atlasUrl?, __bytes?, __vramBytes? }`, plus `name` and `__sourcePath` in development data. `__url` is the layout JSON, `__atlasUrl` the KTX2 beside it (the run's extra output: a build copies both, `devTools/gather/CLAUDE.md`); neither without an output.
- **The layout format** (`FontLayoutFormat.ts`: `FONT_LAYOUT_FORMAT`, `FontLayout`, `FontLayoutGlyph`; types and one constant, `@internal`, on `devTools/engineImports.test.ts`' list): **the one definition**, which the encoder's `devTools/assetPipeline/fonts/layout.ts` imports and re-exports and the parse reads. Minified: `{ format, type, atlas: { file, width, height, size, pxRange }, metrics: { ascender, descender, lineHeight, underlineY (its centre), underlineThickness }, fallback, glyphs, kerningUnitsPerEm?, kerning? }`; a glyph `[advance]` without ink, else `[advance, planeLeft, planeBottom, planeRight, planeTop, atlasX, atlasY, atlasWidth, atlasHeight]` (em to 4 decimals, the plane bounds the tile's whole quad with its range; atlas pixels from the top left, so `v = y / height` on both backends, no flip); `kerning` by first code point, `[second, amount, …]` in `kerningUnitsPerEm` font units (half the bytes of em amounts). A change to what it holds bumps `FONT_LAYOUT_FORMAT` (the runtime refuses another, naming `yarn assets --only <id>`) and the encoder's `FONT_ENCODER_VERSION`.

## Loading fonts

- **`Fonts.ts`** (p391 D6): `FontData` is `{ id, type, atlas, atlasWidth, atlasHeight, size, pxRange, metrics, glyphCount, codePoints (Uint32Array, ascending), advances, planeRects, atlasRects (Float32Array, 4 a glyph), glyphIndices (Map), fallbackIndex, kerning (Map) }`: `planeRects` are `left, bottom, width, height` in em from the pen on the baseline, `atlasRects` `u, v, width, height` in UV with `v` from the top (no flip, D3); a glyph without ink has zeros. Shared by every reader: never written after the parse. `getFontGlyphIndex(font, codePoint)` falls back to `fallbackIndex`. The kerning key is `getFontKerningKey(first, second)`, `first * 0x110000 + second` (not `first << 16 | second`: a code point past the BMP needs 21 bits, and `chars` or a scene's text can hold one), amounts in em (scaled from `kerningUnitsPerEm` at the parse). `parseFontLayout` (`@internal`) refuses another format (before the atlas's download), a glyph entry of another length and a missing fallback glyph, each naming the font and the fix.
- **The atlas is an ordinary registered texture**, `font:<id>` (`getFontAtlasId`), loaded by `loadTextureAsync` from `__atlasUrl` with `LinearFilter` both ways, `generateMipmaps` false, `NoColorSpace` and `throwOnError` (three's `KTX2Loader` gives a `DataTexture` with `NearestFilter`: the load sets them; checked texel-exact on WebGPU and WebGL2, `R8_UNORM` included). So its owners, its release with the scene (once no material samples it), the Assets tab and the GPU memory tab are the kernel's, and its `dispose` event drops the font from the map.
- **The load** (`loadFontAsync(id, { isPersistent })`): the declaration is the development data's `fonts` section, else the first scene entry naming it (production has only the scenes'; an unlisted font rejects there). The layout's fetch and the atlas's load start together at the call, the atlas in the caller's owner scope (taken before the first await); a loaded font is re-tagged to the caller's scope and returned; a call while one loads shares that load and is re-tagged after it. Persistence is the first load's (the atlas's registration): a later `isPersistent` load of a non-persistent font warns. It rejects, naming both files and the fix, for a font without `__url` or `__atlasUrl` (`yarn assets --only <id>`), a layout whose `atlas.file` isn't `__atlasUrl`'s file (generated data older than the outputs: `yarn gatherAppData`) and an atlas of another size than its layout's. `getFont(id)` returns a loaded one.
- **The scene load** (`installFonts`, `text()`'s only install so far): its scene hooks start a scene's `fonts` in `worldCleared` from the next scene's own entries (so they download beside its textures, in its owner scope) and await them in `assetsLoaded`, before the scene code runs. A font that fails is logged naming the scene (`loadSceneFontsAsync`), and the load goes on.
- **The feature** (`TextFeature.ts`, id `text`, in `ENGINE_FEATURE_FACTORIES`) and **the entry** (`index.ts`: the four functions, `FontData`, `FontMetrics`, and the schema's `FontAsset`, `FontCharsetPreset`, `FontType`, `SceneFontDef`; before `aekasha/schemas` in `ENTRY_FILES`, so the font types' API docs are on the text page). In the template's `features` list after `lines()` (p392 Phase 1); its install also installs the texts (`Texts.ts`' `installTexts`: the scene exit's disposal, and `createText` throws naming the feature without it). `getFont` and `loadFontAsync` work without the feature. The texts (`Texts.ts`, `TextObject.ts`, `TextEntity.ts`, `TextLayout.ts`, `TextRegistry.ts`, `TextTypes.ts`; the kernel's `TEXT` component, `{ textId }`) get their sections with p392 Phase 6; until then `docs/plans/p392_text-feature-msdf-renderer.md` is their description.
- **Tests** (`Fonts.test.ts`, on the kernel's own texture registry, owners and scene release, with the KTX2 load, `fetch` and `document` stubbed): the parse (code point order, the typed arrays, a glyph without ink, the rects, the metrics, kerning in em, the fallback, the refusals), the kerning key past the BMP, the load (both downloads started before either ends, the sampler state, a shared load, the declaration's lookup, no data, no output, a 404 and a retry, a wrong atlas size or another encode's atlas, the late `isPersistent` warning), a font's scene (owned, re-tagged, released with its atlas; a persistent one kept), the scene hooks and `text()`.
