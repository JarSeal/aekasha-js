Notes for terrain blocks (`src/_engine/features/terrain/`, the `terrain()` feature, p306); the terrain materials are the toolkit's (`src/toolkit/terrain/CLAUDE.md`); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Terrain blocks

The `terrain()` feature (`TerrainFeature.ts`, id `terrain`, on `aekasha/terrain`; `docs/plans/p306_terrain-blocks-and-procedural-terrain-meshes.md` D2) owns the `*.terrainBlock.json` asset type and its spawner. It doesn't require `physics()`: the install records whether physics was installed before it (`TerrainState.ts`' `terrainState.hasPhysics`), and a block's collider code loads with the first block that has one, so a physics-free app (a landscape embed) loads no Rapier for its blocks. The gather names `physics` in the manifest of a scene listing a block with a collider, so a missing `physics()` is the boot's error. The second feature → feature runtime import after character → physics, and a lazy one (`import()`).

- **The asset** (`TerrainBlockSchema.ts`, on `aekasha/schemas`): `geometry` (`{ importedAsset, node? }` or `{ generator, params?, seed? }`), `material`, `materialInputs` (the material inputs' forms, checked like a material's), `grid` (`x`, `z`, `size`, `resolution`), `collider` (`HEIGHTFIELD` default, `TRIMESH`, `NONE`; `friction`, `restitution`), `shadows`. No `__saveData`. The gather (`devTools/gather/CLAUDE.md`) fills the defaults in (`TerrainBlockDef`) and writes each block a scene lists into its data (`SceneData.terrainBlocks`, the kernel naming the type only), adding its import, material and input textures to the scene's lists. `scatter` / `decals` (p308, p309) aren't fields yet: the strict schema refuses them.
- **Generators** (`TerrainGenerators.ts`): `registerTerrainGenerator(id, fn)` (throws without the feature or on an id taken), `unregisterTerrainGenerator`, `getTerrainGenerator`. A generator gets the block's `params`, `seed` and `grid` and returns `{ geometry, heightfield? }`: the geometry centred, y = 0 its base, `resolution` vertices per side; the heightfield (from `toHeightfieldColliderParams`) when it has the grid at hand, else the collider reads the geometry. The engine registers none; the toolkit's `noiseTerrain` and `rulesTerrain` (`registerTerrainGenerators()` on `aekasha/toolkit/terrain`, `src/toolkit/terrain/blocks/`, their code `import()`ed with the first block using one) are registered by the app's install (`appECSPlugins`); they generate through `generateTerrainAsync` (`aekasha/toolkit/geometry`, p306 Phase 4), on the toolkit's own terrain worker, so a spawn doesn't block the main thread for the generation (a generator may return a promise, so an app's can use it too). No generator reads a heightmap yet (a heightmap isn't an asset the gather knows: `docs/plans/p990_follow-ups-from-done-plans.md`); a heightmap block is scene code, `loadTerrainHeightmapAsync` and `generateTerrainAsync`'s `heightmap` option, as `terrainBlockTest`'s front block. A height noise continuous across blocks takes the block's seed as it is, sampled at its world place (`grid × size`); a block's own randomness mixes the seed with `grid.x` / `grid.z`.
- **The spawn** (`TerrainBlocks.ts`' `spawnTerrainBlock(id, { appId? })`): the block from the loading scene's data, else the current one's (`getTerrainBlock`); throws when the scene doesn't list it, its import isn't loaded or has no single mesh for `node` (none: the import's only mesh), its generator isn't registered, or its collider needs a `physics()` that isn't installed. The mesh is `createMeshEntity` at `(x · size, 0, z · size)` (an imported node's transform is ignored, with a warning), its material the block's own or `getMaterialVariant(material, { inputs })`, its app id `terrainBlock/<id>`; a generated geometry is registered with `saveBufferGeometry`, owned by the scene and disposed with its last mesh. The collider (`TerrainCollider.ts`, `import()`ed on the first block with one) is a `FIXED` body on the mesh entity, its shape the generator's heightfield or `deriveColliderFromGeometry` on the geometry (a `HEIGHTFIELD` of `resolution - 1` cells per side, read by position; an imported node with the identity transform, a generated one with a stand-in manifest entry, `terrainBlock:<id>` in the messages); a geometry that gives no shape logs and leaves the block without one. The result is `{ id, meshEntityId, physicsEntityId?, scatterIds, decalIds, dispose() }` (`physicsEntityId` is the mesh entity; the two lists empty until p308 / p309).
- **A scene left meanwhile:** the install's `exit` hook counts the exits (`terrainState.sceneVisit`); a spawn whose count changed across an `await` (the generator, the collider's `import()` or create) deletes what it made (an unregistered generated geometry disposed, the mesh entity with its body) and resolves with `null`.
- **Blocks from Blender** (p306 Phase 5): the toolkit's add-on `src/toolkit/terrain/blender/aekasha_terrain_tools.py` (Blender 5.3, one file, Install from Disk; its header and sections say how) makes an imported block that follows D1: Add (the grid at exact positions, triangles along the heightfield's diagonal, the top-down UVs, a byte vertex-domain `Splat`, D1's custom props plus `keepMesh`), Validate, Normalize Splat, the preview material, Bake AO → Splat Alpha, Bake Colour Map, Split Into Blocks and Export (the locked glTF settings, from a copy at the origin; the GLB, the images, and only the JSON stubs that aren't there: an `importedAsset` with `"profile": "terrainBlock"`, a `terrainBlock` with a placeholder material, each image's texture with `flipY: false`). The engine's (x, y, z) is Blender's (x, −z, y); the grid's row 0 and V 0 are the engine's −z edge, the top view's top and a splat image's top row. A painted splat image is set Non-Color before painting: Export saves its bytes as they are. `yarn verify:blender` checks it in a real Blender and reads its GLBs as the import does (`devTools/verify/CLAUDE.md`); `terrainBlockTest`'s orientation block (`blenderBlock/`, made by `devTools/blender/exportOrientationBlock.py`) is an export drawn through its `COLOR_0` and its splat map, its test pinning the orientation in the files.
- Tests: `TerrainGenerators.test.ts`, `TerrainBlocks.test.ts` (the kernel calls stand-ins), `TerrainCollider.test.ts` (the shapes from a real grid, the physics entity a stand-in).
