Notes for terrain blocks and decal sets (`src/_engine/features/terrain/`, the `terrain()` feature, p306, p309); the terrain materials are the toolkit's (`src/toolkit/terrain/CLAUDE.md`); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Terrain blocks

The `terrain()` feature (`TerrainFeature.ts`, id `terrain`, on `aekasha/terrain`; `docs/plans/_DONE_p306_terrain-blocks-and-procedural-terrain-meshes.md` D2) owns the `*.terrainBlock.json` asset type and its spawner. It doesn't require `physics()`: the install records whether physics was installed before it (`TerrainState.ts`' `terrainState.hasPhysics`), and a block's collider code loads with the first block that has one, so a physics-free app (a landscape embed) loads no Rapier for its blocks. The gather names `physics` in the manifest of a scene listing a block with a collider, so a missing `physics()` is the boot's error. The second feature → feature runtime import after character → physics, and a lazy one (`import()`).

- **The asset** (`TerrainBlockSchema.ts`, on `aekasha/schemas`): `geometry` (`{ importedAsset, node? }` or `{ generator, params?, seed? }`), `material`, `materialInputs` (the material inputs' forms, checked like a material's), `grid` (`x`, `z`, `size`, `resolution`), `collider` (`HEIGHTFIELD` default, `TRIMESH`, `NONE`; `friction`, `restitution`), `shadows`, `scatter` (p308) and `decals` (p309 D3: decal set ids). No `__saveData`. The gather (`devTools/gather/CLAUDE.md`) fills the defaults in (`TerrainBlockDef`) and writes each block a scene lists into its data (`SceneData.terrainBlocks`, the kernel naming the type only), adding its import, material and input textures to the scene's lists, its `scatter`'s ids to the scene's `scatters` (p308 D2: the gather fails on an id no `*.scatter.json` has) and its `decals`' to its `decalSets` (likewise).
- **Generators** (`TerrainGenerators.ts`): `registerTerrainGenerator(id, fn)` (throws without the feature or on an id taken), `unregisterTerrainGenerator`, `getTerrainGenerator`. A generator gets the block's `params`, `seed` and `grid` and returns `{ geometry, heightfield? }`: the geometry centred, y = 0 its base, `resolution` vertices per side; the heightfield (from `toHeightfieldColliderParams`) when it has the grid at hand, else the collider reads the geometry. The engine registers none; the toolkit's `noiseTerrain` and `rulesTerrain` (`registerTerrainGenerators()` on `aekasha/toolkit/terrain`, `src/toolkit/terrain/blocks/`, their code `import()`ed with the first block using one) are registered by the app's install (`appECSPlugins`); they generate through `generateTerrainAsync` (`aekasha/toolkit/geometry`, p306 Phase 4), on the toolkit's own terrain worker, so a spawn doesn't block the main thread for the generation (a generator may return a promise, so an app's can use it too). No generator reads a heightmap yet (a heightmap isn't an asset the gather knows: `docs/plans/p990_follow-ups-from-done-plans.md`); a heightmap block is scene code, `loadTerrainHeightmapAsync` and `generateTerrainAsync`'s `heightmap` option, as `terrainBlockTest`'s front block. A height noise continuous across blocks takes the block's seed as it is, sampled at its world place (`grid × size`); a block's own randomness mixes the seed with `grid.x` / `grid.z`.
- **The spawn** (`TerrainBlocks.ts`' `spawnTerrainBlock(id, { appId? })`): the block from the loading scene's data, else the current one's (`getTerrainBlock`); throws when the scene doesn't list it, its import isn't loaded or has no single mesh for `node` (none: the import's only mesh), its generator isn't registered, or its collider needs a `physics()` (its scatters an `instancing()`) that isn't installed. The mesh is `createMeshEntity` at `(x · size, 0, z · size)` (an imported node's transform is ignored, with a warning), its material the block's own or `getMaterialVariant(material, { inputs })`, its app id `terrainBlock/<id>`; a generated geometry is registered with `saveBufferGeometry`, owned by the scene and disposed with its last mesh. The collider (`TerrainCollider.ts`, `import()`ed on the first block with one) is a `FIXED` body on the mesh entity, its shape the generator's heightfield or `deriveColliderFromGeometry` on the geometry (a `HEIGHTFIELD` of `resolution - 1` cells per side, read by position; an imported node with the identity transform, a generated one with a stand-in manifest entry, `terrainBlock:<id>` in the messages); a geometry that gives no shape logs and leaves the block without one. Its scatters (p308 D2: `features/instancing/Scatter.ts`, `import()`ed after the collider with the first block that has one; `terrain()` records `ctx.isInstalled('instancing')` as it does physics) spawn on the block, `target` its centre, grid place, size and mesh entity, their app ids `<appId>/scatter/<id>`; a scatter that throws deletes the block first. Its decal sets spawn last, at the block's grid place (`spawnDecalSet` with the block's position as the root transform: a set is exported in the block's own space), their app ids `<appId>/decals/<id>`; one that throws deletes the block first. The result is `{ id, meshEntityId, physicsEntityId?, scatterIds, decalIds, dispose() }` (`physicsEntityId` is the mesh entity; `scatterIds` each scatter's cells, then its colliders; `decalIds` each decal set's meshes); `dispose()` deletes the scatters and decal sets first.
- **Decal sets** (p309 D3: `DecalSetSchema.ts` on `aekasha/schemas`, `DecalSets.ts`' `spawnDecalSet(id, { transform?, appId? })` and `getDecalSet` on `aekasha/terrain`): a `*.decalSet.json` names an import whose meshes are decals (planes UV'd into a decal atlas's cells, with a second UV set `uv1` 0..1 over the decal for the decal material's edge fade, conformed to a block in Blender), its decal `material`, `renderOrder` (default 10: the bands, terrain 0, decals 10, other transparents 20 and up) and `receiveShadow` (default true). The gather (`devTools/gather/decalSets.ts`) fills the defaults in (`DecalSetDef`, `SceneData.decalSets`) and adds its import and material to a scene listing it in `decalSets` (the scene field, `terrain` in the manifest) or through a block's `decals`. The spawn is a typed `spawnImportedAsset`: the set's material, `castShadow: false`, its `receiveShadow`, its render order on every node (`meshProps`), app ids `decalSet/<id>/<node>`, no physics; a node with physics custom props or GPU instances isn't a decal (skipped, warned: an instance cell would draw at render order 0), and one without `uv1` is warned of (the toolkit's decal materials draw nothing there). A node's `merge` custom prop reaches the import's spawn (a `CUTOUT` set into a `BAKED` group, a `BLEND` one into a `BATCHED` group). It throws when the scene doesn't list the set or its import or material isn't loaded.
- **A scene left meanwhile:** the install's `exit` hook counts the exits (`terrainState.sceneVisit`); a spawn whose count changed across an `await` (the generator, the collider's `import()` or create, a scatter's or a decal set's spawn) deletes what it made (an unregistered generated geometry disposed, the mesh entity with its body) and resolves with `null`.
- **Blocks from Blender** (p306 Phase 5): the toolkit's add-on `src/toolkit/terrain/blender/aekasha_terrain_tools.py` (Blender 5.3, one file, Install from Disk; its header and sections say how) makes an imported block that follows D1: Add (the grid at exact positions, triangles along the heightfield's diagonal, the top-down UVs, a byte vertex-domain `Splat`, D1's custom props plus `keepMesh`), Validate, Normalize Splat, the preview material (its weights the group's inputs: the `Splat` attribute, or a block's splat map), New Splat Map (`<id>_splat0`, Non-Color, channel-packed, drawn by the block's own preview material for Texture Paint), Bake AO → Splat Alpha, Bake Colour Map, Split Into Blocks and Export. A block's Collider setting (`HEIGHTFIELD`, `TRIMESH`, `NONE`) sets its custom props and stub; a `TRIMESH` block skips Validate's grid, face, UV and edge checks (overhangs, caves). The templates (`terrain_*.blend`, `structure_concrete.blend`, D6) are made by `devTools/blender/buildTerrainTemplates.py` (its header has the command) (the locked glTF settings, from a copy at the origin; the GLB, the images, and only the JSON stubs that aren't there: an `importedAsset` with `"profile": "terrainBlock"`, a `terrainBlock` with a placeholder material, each image's texture with `flipY: false`). The engine's (x, y, z) is Blender's (x, −z, y); the grid's row 0 and V 0 are the engine's −z edge, the top view's top and a splat image's top row. A painted splat image is set Non-Color before painting: Export saves its bytes as they are. `yarn verify:blender` checks it in a real Blender and reads its GLBs as the import does (`devTools/verify/CLAUDE.md`); `terrainBlockTest`'s orientation block (`blenderBlock/`, made by `devTools/blender/exportOrientationBlock.py`) is an export drawn through its `COLOR_0` and its splat map, its test pinning the orientation in the files. **Decal sets from Blender** (p309 D3, the add-on's Decal Sets panel): Add Decal Set makes a collection for the active block (`collection.aek_decal_set`: its id, block, atlas, material, folder); Add Decal adds a cell of a decal atlas (read from the repo's `*.textureAtlas.json`s with the `DECAL` slots, rect cells only: the UV rect is the gather's cell table, V flipped for Blender) at the 3D cursor at its `physicalSize`, a quad or (a `tileAlong: 'U'` cell) a strip with its own path curve. A decal's UV maps are `UVMap` (TEXCOORD_0, the cell) and `DecalUV` (TEXCOORD_1, the engine's `uv1`); its modifiers Array (fit to the path), the Geometry Nodes group "AEK Decal" (Subdivide by its Level, which Add Decal sets to a face of at most half the block's grid spacing: at the spacing a face spanning a fold of the block's triangles cut 6 mm into bumps; then `DecalUV` from the bounds: **the Array's UV offset moves every UV map**, so it can't make a strip's `uv1`), Curve, Shrinkwrap (project along Z both ways, above the surface, 0.015 m). Export Decal Set bakes each decal's modifiers (`new_from_object`), places it from the block's origin, exports one GLB (`DECAL_EXPORT_SETTINGS`: the locked ones, no colour or attributes), writes the stubs it lacks (`<setId>.importedAsset.json` with the default mesh encode: meshopt, quantized, about 2 mm on a 35 m set and a quarter texel of a 2K atlas, against the 1.5 cm offset; 2.6 × smaller than the lossless `terrainBlock` profile; `<setId>.decalSet.json`) and reads the GLB back. In Blender 5 a Geometry Nodes modifier's input is `modifier.properties.inputs.<identifier>.value` (4.x's `modifier[identifier]` is refused). Blender can't read the atlas's KTX2, so its decals draw a stand-in (`AEK Decal Preview`: a dark stain by the edge fade). Its template is `terrain_decals.blend`; `terrainBlockTest`'s decal block (`decalBlock/`, made by `devTools/blender/buildDecalTest.py`, which also prints how far the decals lie from the block across their faces for levels 1-4) is the check: two tyre tracks over a ridge with bumps, spawned through the block's `decals`.
- Tests: `TerrainGenerators.test.ts`, `TerrainBlocks.test.ts` and `DecalSets.test.ts` (the kernel calls stand-ins), `TerrainCollider.test.ts` (the shapes from a real grid, the physics entity a stand-in).
