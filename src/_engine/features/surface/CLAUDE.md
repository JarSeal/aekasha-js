Notes for the surface conditions (`src/_engine/features/surface/`, the `surfaceConditions()` and `rainOcclusion()` features on `aekasha/surface`, p307; the wet response that reads them is the toolkit's, `src/toolkit/terrain/CLAUDE.md`); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Surface conditions

One global state of the weather on the ground (p307` D1 and Phase 1's As built), which wet materials read through stable uniforms: `wetness`, `rain`, `puddleLevel` (0..1 each), `waterLevel` (a world Y or `null`), `snowCoverage` (0..1), `temperature` (°C), `dryingRate` (per minute), `wind` (`[x, z]` m/s) and `mode` (`SIMULATED`, `MANUAL`). The how-to is the handbook's `docs/techniques/wet-dry-surfaces.md`.

- **Where the parts are.** `SurfaceConditionsModel.ts`: the state's type and defaults (`SURFACE_CONDITIONS_DEFAULTS`), the transitions, the rain's stop and the simulation, as plain functions of a state and a step (no three, no ECS; the tests drive it). `SurfaceConditions.ts`: the running state (made at the install, null before), the uniforms, the surface clock, `surfaceConditionsSystem` and the public API. `SurfaceConditionsSchema.ts`: the scene's part (`surfaceConditionsSchemaPart`, `SceneSurfaceConditionsSchema`, on `aekasha/schemas`; last in `ENGINE_SCHEMA_PARTS`), so a scene that sets `surfaceConditions` names the feature in its manifest. `SurfaceConditionsFeature.ts`: `surfaceConditions({ timeSource? })`, id `surfaceconditions`. `debug/_dbg__SurfaceConditions.ts`: the tab.
- **Without the feature** the getters (`getSurfaceConditions`, `getSurfaceConditionNodes`, `getSurfaceTime`) return null and the setters throw naming the factory; a material with the toolkit's `wet` builds dry, warned once a page load.
- **Stable uniforms.** `getSurfaceConditionNodes()` makes the nodes on its first call (none at load: no module side effect) and returns the same ones for the app's lifetime (`wetness`, `rain`, `puddleLevel`, `waterLevel`, `snowCoverage`, `temperature`, `wind` (vec2), `time`), so a material binds them once at build and never goes stale (the sky's per-activation uniforms are the trap this avoids). The system writes them every frame, a setter at once, in place: nothing allocates. Without a water level the uniform is `SURFACE_WATER_LEVEL_NONE` (−1e9): JSON has no −Infinity, so `waterLevel` is `number | null`. `dryingRate` and `mode` have no uniform (the CPU's).
- **The surface clock** (`getSurfaceTime()`, the uniform `time`; the ripples', the streaks' pulses and the shore's waves): seconds, advanced by `getElapsedTime()`'s change, like the sky clock. `timeSource` `APP` (default) stops with the app loop's pause (F7, `sc-toggle-app-pause`), `MAIN` only with the master loop; never while a scene loads (`isCurrentlyLoading`). The test bridge's `freeze()` pauses the loops, so it holds the clock with no change of its own, and the scene runner's snapshots of a wet scene are the same every run.
- **`surfaceConditionsSystem`** (`MAIN`, order 1, default world only; registered at the install through `ctx.registerPlugin`): with `skyBoxSystem`, after it by install order (the template lists `surfaceConditions()` right after `skyBox()`), so the sun source reads this frame's sun. Each frame: the clock, the transitions (`stepSurfaceDynamics`), the simulation (`stepSurfaceSimulation`, `SIMULATED` only), the uniforms.
- **The simulation** (per minute of the surface clock; the model's constants): `rain` wets at its intensity (`SURFACE_WETTING_PER_MIN` 1: dry to soaked in a minute); drying is `dryingRate × sunFactor × windFactor × (1 − rain)`; `puddleLevel` rises toward `wetness` at 0.5 and drains toward it at half the drying; snow melts 0.02 a °C above 0, all of it into `wetness`. `sunFactor` is `clamp(sin(elevation), 0.2, 1)`, 1 without a sun; `windFactor` 1 in still air to 3 at 20 m/s and over. A value under a transition is the transition's, not the simulation's.
- **Transitions:** `setSurfaceConditions(input, { transitionSec? })` moves each number linearly (the wind's two); a value set while it moves restarts from where it is. `mode` and a water level from or to `null` switch at once. Out-of-range values are clamped, non-finite ones ignored. `startRain(intensity, { rampSec?, durationSec? })` ramps the rain (`durationSec`: it stops by itself, ramping down as long), `stopRain({ rampSec? })` ramps it to 0.
- **The sun source** (`setSurfaceSunSource(() => number | null)`, radians): no feature imports another's code but character → physics, so the app ties drying to its sky; the template's `appECSPlugins` sets `() => getSunElevation()` in its install. p427 (weather and mood) would move the time of day out of the sky box: only that line changes.
- **The scenes** (`surfaceConditionsSceneHooks`): `exit` resets the state to the defaults with no transition and the clock to 0; `worldCleared` applies the next scene's JSON `surfaceConditions`, before its scene code (which can set its own). So a scene looks the same on every visit. The state never runs while a scene loads.
- **The debug tab** "Surface conditions" (`surfaceConditionsControls`, after `skyBoxControls` in `DEFAULT_DEBUG_DRAWER_TAB_ORDER`; `keepOnSceneChange`, every field read through getters, so no LS, overrides or undo, like the day-night transport): Weather (a rain shower: 10 s up, 60 s, 10 s down; stop rain; dry now; soak; snowfall: −5 °C, the cover over 30 s), Conditions (runtime) (the mode, every value, the water level's switch and y), Simulation (the surface clock, the sun and wind factors), and with `rainOcclusion()` the map's folder (below). Its icon is the built-in `droplet` (`aekasha/ui`'s `dropletIcon`).
- **Size:** the feature's modules are in the app's first download (the `_engine/features/surface` group in `sbp.config.ts`, the rain occlusion map's with them), the tab a debug chunk; the banner has none (`FEATURE_GROUPS`).
- **Gameplay:** the state is visual and runs at frame time. Anything that changes the simulation (wet friction, p307 T14) needs the step clock and the seeded streams (the root's Physics rules); a surface query for it is a follow-up.

## Rain occlusion map

`rainOcclusion(opts?)` (p307 T12, Phase 6's As built; id `rainocclusion`, `requires: ['surfaceconditions']`, listed right after it, `physicsTiers()`'s precedent of two features on one entry): a depth map rendered straight down around the active camera, so a wet material stays dry, unpuddled and unsnowed under roofs, trees and bridges. An app without it carries none of the render.

- **Where the parts are.** `RainOcclusionModel.ts`: the options (`RainOcclusionOpts`), their defaults and checks (out of range throws at the factory's call), the texel snap and when to render (plain functions). `RainOcclusion.ts`: the map, its render, `rainOcclusionSystem`, the node and the API. `RainOcclusionFeature.ts`: the factory. Tests: the model's, and `RainOcclusion.test.ts` on a fake renderer (when it renders, the state put back, the matrix's orientation and depth).
- **Options:** `size` (texels a side, 16-4096, 512), `extent` (metres a side, 64), `height` (metres above and below the camera, 100), `updateFrames` (30; 0 renders only on a move or a request), `bias` (metres, 0.05).
- **The map:** a `RenderTarget` with an R8 colour nothing writes and a `DepthTexture` with a compare function and linear filters (hardware PCF: one fetch filters 2 × 2 texels; `FloatType` and `GreaterEqualCompare` under a reversed depth buffer), and an `OrthographicCamera` looking straight down (its up the world's −z), `extent` wide and `2 × height` deep, its top `height` above the active camera, centred on it snapped to the texels (so the map doesn't shimmer as the camera moves).
- **The render** (`rainOcclusionSystem`, `MAIN`, order 1, after `surfaceConditionsSystem` by install order; default world only), three's shadow pass's way (r187 `ShadowNode.updateShadow`): the renderer's and the scene's state saved and put back (`RendererUtils`, its scratch states kept), the root scene drawn with an override material (depth only, both faces; three gives it each object's `positionNode`, alpha test and alpha map), a render object function drawing the occluders only, with the active camera's layers, without the background or fog. **Occluders** are what casts shadows, overridden per object by a boolean `userData.rainOccluder` (`isRainOccluder`). It renders while a material has made a node, the map is on and no scene loads: first, on `requestRainOcclusionUpdate()`, when the camera has moved an eighth of the extent across or of the height up or down from the map's centre, and every `updateFrames` frames. It allocates nothing.
- **The node** (`getRainOcclusionNode({ position?, normal? })`, 0 open to 1 sheltered; null without the feature; its first call starts the renders): the world position pushed out along the geometry normal by 1.5 texels (a wall's face and a slope look past their own top), through the shadow matrix (bias × projection × view; z kept in [0, 1] on WebGPU, mapped there on WebGL), v flipped (three's shadow coordinates), the depth moved toward the map's camera by `bias` (an occluder doesn't shelter its own top); `1 − compare`, × the edge fade (open over the map's last tenth from each edge), × inside the depth range (above or below it: open), × a `strength` uniform (1 while on and rendered since the scene's start). **A compare fetch needs uniform control flow:** sample it outside any `If` (the toolkit's wet response does it at the graph's top level).
- **The scenes** (`rainOcclusionSceneHooks`): `exit` drops the map (strength 0, a render requested), and the next scene's `worldCleared` makes the target and clears it once, outside any render and before its scene code can build a material that samples it: a target sampled before its first render loses its texture in place (the destroyed-texture trap, `src/_engine/features/skybox/CLAUDE.md`). Until the system's first render the node reads open sky. The target lives across scenes; `onUnmount` (`stopRainOcclusion`) disposes it.
- **API:** `getRainOcclusionNode`, `setRainOcclusionEnabled(isEnabled)` (off: every node reads open sky and nothing renders; on again renders on the next frame), `isRainOcclusionEnabled()` (null without the feature), `requestRainOcclusionUpdate()`; the setters throw without the feature, naming it.
- **Debug:** the surface tab's "Rain occlusion map" folder (with the feature): the switch, the frames between renders (`setRainOcclusionUpdateFrames`), the status (idle until a material reads it), the map's size, the renders, renders a second, the CPU and GPU ms a render (`createBakeStats` through `_setRainOcclusionRenderHooks`, set when the tab's module loads: without hooks a render reads no clock) and the centre. The tab module exports the stats view (`rainOcclusionStatsView`) for a measuring script.
- **Cost** (Phase 6, the gallery's 512² map over 64 m, three small occluders, every frame; Windows Chrome on an AMD RDNA 3 GPU): 0.26 ms CPU a render on average (three's projection walks the whole scene, so it grows with the scene's objects, not the occluders), 0.005 ms GPU; at the default 30 frames about 0.01 ms CPU a frame. Memory: the 512² depth texture (1 MiB) and its R8 colour (0.25 MiB). A material pays one compare fetch a pixel; the terrain material's budget doesn't count the map (it's within `reservedTextures`).
- **Not done:** the rain falls straight down (tilting the map by the wind is a p990 follow-up); a shadow-casting ground in the map hasn't been seen on a GPU (the gallery's row casts no shadows).
