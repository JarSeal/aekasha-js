Notes for the UI kit (`src/_engine/ui/`, `aekasha/ui`: CMP, the HUD root, the draggable windows, dialogs, the drop-down, toasters, icons and the styles); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## UI kit

The DOM UI the app's HUD and the debug tools are built from, public on `aekasha/ui` (p617 D6). The Hub's UI kit page is the user guide, and its example scene (`src/app/examples/uiKit/`) builds an app HUD from every piece. p800 restyles the kit and adds components; until then a change here keeps its look.

- **CMP** (`CMP.ts`; its types in `CMPTypes.ts`, the animation chain in `CMPAnim.ts`, which writes the CMP through its methods and imports only the types): `CMP(props, wrapper?, wrapperProps?)` makes an element from its props (`tag`, `text`, `html`, `class`, `style`, `attr`, the `on*` listener props and `listeners`, `anim`, `onCreateCmp` / `onRemoveCmp`) and returns its handle, `TCMP` (`add`, `remove`, `update`, `updateText`, `updateClass`, `updateStyle`, `updateAttr`, `focus`, …). `classes(...)` joins class arguments.
  - It's in the DOM once it's added under a CMP that is: an app's UI goes under the HUD root (`getHUDRootCMP().add(…)`). The one root is the CMP made with `attach` (the boot's HUD root): a second one throws, and so does a taken id. A generated id is a counter (`aekCmp_N`).
  - Templates: a CMP's `toString()` is a `<cmp>` placeholder, so another CMP's `html` places it (`` html: () => `<h2>${star} Scores</h2>` ``). The parent's `update()` makes its template children again, so an `html` that names them is a function. `html` is raw HTML: user text goes in `text`, or through the root's `settings.sanitizer` (`sanitize`, `sanitizeAll`).
  - Props are copied once, at create and at `update()` (`style` and `attr` too, so a style constant several CMPs share is never written). The update methods write that copy in place, with no allocation per call (a HUD value updated every frame), and the next `update()` keeps what they set.
  - `onCreateCmp` runs once when the CMP is mounted (added, attached, or put in place of its placeholder by its parent's `html`) and after each `update()`; `onRemoveCmp` after `remove()` has removed its children, listeners, timers and element. Per-CMP state kept in a module map is cleaned up there.
  - Every listener is a capture listener (a `listeners` entry is added with `{ capture: true, ...options }`): a parent's `onClick` runs before its child's, and a child's `stopPropagation()` doesn't stop it.
  - A style key that is a custom property (`--x`) goes through `setProperty` / `removeProperty`; `null` removes a style.
- **The HUD root** (`HUD.ts`): made by the boot (`createHudContainer`, `@internal`), a fixed, zero-size element over the canvas in place of the page's `#hudRoot` or `#guiContainer`, or of a mount's slot in its container (whose `contain: layout` makes the HUD's fixed elements relative to the container). Each child places itself. In an editor view only the root's direct children with `KEEP_IN_VIEWS_CLASS` stay visible (the root's Views section).
- **Draggable windows** (`DraggableWindow.ts`: the stacks, the DOM build, the hooks and the public functions, over 800 lines with its header saying why; `DraggableWindowTypes.ts`, `DraggableWindowStore.ts` (config resolution, LS, the kinds' geometry), `DraggableWindowGeometry.ts` (styles, clamps, fits, cascade) and `DraggableWindowDrag.ts`, none of which imports `DraggableWindow.ts`; `DraggableWindow.module.scss`):
  - `openDraggableWindow({ id, title, content, … })` opens a window, or reopens and updates the one with its id. `closeDraggableWindow` keeps its state (a reopen restores its layout), `removeDraggableWindow` drops it. Two layers: the app's windows, and the debug windows (`isDebugWindow`) above them, opened only in the debug env (`showInProdTest`: prodTest too).
  - An edit window per entity is a window kind. Register the kind once with `registerDraggableWindowKind(kind, { content, onClose, sceneTargetResolver, keepInViews })`, before the boot restores the saved windows (its step after the app's `start`): in `start` or a feature's install, or at a `_dbg__` module's load (anywhere else a registration at load is a module side effect). It also covers the windows restored from LS; a single window uses `registerDraggableWindow(id, …)`. Open a window with `kind` and `id: getKindWindowId(kind, key)`, from a list row through `toggleDraggableWindow` (open, bring to front, close when on top), and select the rows from `getDraggableWindowsOfKind`. Rebuild one with `updateDraggableWindow(id)`, all with `updateDraggableWindowsOfKind(kind)`, and keep per-window module state in a map cleaned up in the content's `onRemoveCmp`. Double-clicking a header fits the window to the screen (`fitDraggableWindowToScreen`), and the Debug tools tab's "Center and fit all windows" fits them all (`fitAllDraggableWindowsToScreen`).
  - LS: the `saveToLS` windows and the kinds' geometry are in `AEK_popupWindows`, written on finished changes and restored by the boot's after-start hook; a restored window's content comes from its registered function, which is why registering comes first. The format is unchanged since before p617's split (`DraggableWindow.test.ts`' round trip).
  - Scene loads: at a load's start a `removeOnSceneChange` window is removed, and a `closeOnSceneChange` one closes, unless its kind has a `sceneTargetResolver`: then it's torn down and rebuilt after the `entered` hooks when the resolver finds its target in the next scene (closed otherwise, and after a failed load, at `loadSettled`).
  - The kernel names it uses (p617 D7, the only ui → kernel imports `moveMap.ts`' `checkEdge` allows, `UI_KERNEL_HOOKS`): `addSceneHooks`, `addResizer`, `addBootAfterStartHook`, added on the windows' first use, never at load, and `Config.ts`' env flags (and `AppConfig.draggableWindows`, the deprecated fallback for a content function, until 6.0.0).
  - A window's `icon` is a registered icon's name (see Icons).
- **Dialogs** (`DialogWindow.ts`): `openDialog` is a window centred over a backdrop that doesn't move, resize or collapse, reset on every open. With `closeOnEscape`, Escape closes the top such dialog and nothing else gets that press or its keyup: two capture listeners on the window, added by the first such dialog and kept (a no-op while none is open).
- **The drop-down** (`DropDown.ts`, `DropDown.scss`): `createDropDown` returns `{ cmp, open, close, toggle, isOpen, refresh }`; add its `cmp` where it goes. Keyboard, focus and ARIA are its own, and the list's keys reach no key binding. The trigger's label re-reads `value` after `onChange` returns (p617 Phase 6); `refresh()` is for a change made elsewhere.
- **Toasters** (`Toaster.ts`): `createToaster` returns the toaster's CMP (add it under the HUD root) and puts its CSS in the head; the first one made is the default for `addToast` (`setAsDefaultToaster` moves it). One timer per toast at a time; `removeToaster` clears its toasts' timers and its styles. The engine makes a toaster only in the debug env (the debug toaster, kept in every view), so an app that shows toasts makes its own.
- **Icons** (`icons/`): `registerIcon(name, svg)` and `getSvgIcon(name, size?)`; the built-ins are named SVG strings (`BuiltInIcons.ts`, from `icons/svg/`, Bootstrap Icons' licence). The boot registers them all (`registerBuiltInIcons`, about 10 kB gzip) only in the debug env and prodTest: a production app registers the ones it shows, or gets `??` and a warning.
- **Styles** (`styles/`): `index.scss`, which `Boot.ts` imports in every build, holds only the editor views' HUD rule and `.uiIcon`: nothing on an element a host page owns, nothing of the debug tools (each debug module imports its own, p617 S1). `page.scss` (`InitEngine` only): normalize and the `html` and `body` rules, among them `font-size: 62.5%`, which the kit's `rem` sizes assume. A component's styles come with its module (`DraggableWindow.module.scss`, `DropDown.scss`, the toaster's injected CSS). `variables.scss` is mostly the debugger's colours (p800's).
- **In an embed** (`mountAekasha`; filed for p800, `docs/issues/ui-kit-in-an-embed.md`): `page.scss` isn't loaded, so the kit's `rem` sizes follow the host page's root size (1.6× at the browsers' 16 px), and the windows measure the browser window (`getWindowSize`, `@internal`), not the container, with `100vw` × `100vh` as the default max size. No embed shows kit UI yet.
- Tests (Node, linkedom stubbed per file): `CMP.test.ts`, `DraggableWindow.test.ts` (the hooks added on first use and never at load, the reopen rules, kinds, scene loads, the LS round trip), `DialogWindow.test.ts`, `Toaster.test.ts`, `DropDown.test.ts`. linkedom takes `style['--x']`, which browsers ignore, so the custom-property path is checked in a browser only.
- Waiting for engine 6.0.0 (p622): the `T`-prefixed type names (`TCMP` → `Cmp`, `TProps` → `CmpProps`, …), `AppConfig.draggableWindows`, `AddToastResponse.timeout` and `TSettings.doCheckIsInDom`.
