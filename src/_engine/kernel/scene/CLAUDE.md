## Scene loads

Scene loads (`loadScene`, `kernel/scene/SceneLoader.ts`, p613 D3) run one at a time: a call during a load waits for it, and a later call replaces the waiting one, which resolves `false` without loading. `loadScene` resolves `true` once the scene is current and `false` when it failed or was replaced, and never rejects, so scene code and scene hooks never await it (the call would wait for the load it runs in). The steps: `resolveLoadTarget` (an unknown scene, scene code or loader throws before anything changes), `beginLoad`, `tearDownPrevScene`, `loadNextSceneAsync`, `enterSceneAsync`, then `finishLoad` for both outcomes: a failed load turns the inputs, the canvas's pointer events and the debugger back on, hands the asset owner back to the current scene and leaves that scene current. It's a promise chain, not a `try`, so its debug-gated calls fold. What a load builds from the scene's data is in `kernel/scene/SceneDataLoader.ts` (`@internal`): `createCameras` first, `loadNextSceneAssets` (a material's texture ids resolved into a copy, never into the cached generated params), and after the scene code `createNextSceneObject3Ds` (the lights and meshes). The glTF import path (`kernel/assets/import/ImportRegistry.ts`) loads with an `import()` only for a scene whose data names an imported asset, by id or inline (p613 D4), and hands `SceneAssetRelease.ts` its release on its first import (`setSceneImportRelease`), so a scene file's own `importAssetAsync` is released with its scene too.

Next to `?isDebug=true` or `?isProdTest=true` (the root `CLAUDE.md`'s Commands), `?startScene=<sceneId>` (`getStartSceneQueryParam`; null outside those two modes, so a production build never reads it) picks the first scene: `loadScene`'s first load (`kernel/scene/SceneLoader.ts`) uses it over the Debug tools' start scene and `src/index.ts`'s, with the scene code from the data's `sceneFiles` (`getAppData()`, the generated `sceneFileObjects`). An id without both its scene data and its scene file warns (also as a debug toast, queued by `addDebugToastWhenReady` until the toaster exists) and loads the usual start scene. Later loads ignore it; the debugger's scene loader still applies only while the Debug tools' start scene is on.
