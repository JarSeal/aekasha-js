## Scene loads

Scene loads (`loadScene`, `kernel/scene/SceneLoader.ts`, p613 D3) run one at a time: a call during a load waits for it, and a later call replaces the waiting one, which resolves `false` without loading. `loadScene` resolves `true` once the scene is current and `false` when it failed or was replaced, and never rejects, so scene code and scene hooks never await it (the call would wait for the load it runs in). The steps: `resolveLoadTarget` (an unknown scene, scene code or loader throws before anything changes), `beginLoad`, `tearDownPrevScene`, `loadNextSceneAsync`, `enterSceneAsync`, then `finishLoad` for both outcomes: a failed load turns the inputs, the canvas's pointer events and the debugger back on, hands the asset owner back to the current scene and leaves that scene current. It's a promise chain, not a `try`, so its debug-gated calls fold. What a load builds from the scene's data is in `kernel/scene/SceneDataLoader.ts` (`@internal`): `createCameras` first, `loadNextSceneAssets` (the scene's `textures`, which hold the gather's texture closure too, the textures its materials, spot lights' cookies and `backgroundTexture` name without listing them (p302 D6, `devTools/gather/CLAUDE.md`), loaded as listed ones: the loader didn't change; a material's texture ids resolved into a copy, never into the cached generated params), the `assetsLoaded` scene hooks (p374: what's made from the assets before the scene code uses it, merging's merge materials), and after the scene code `createNextSceneObject3Ds` (the lights and meshes). A material code creates outside a load gets its textures and TSL file from `ensureMaterialDependencies` (`kernel/assets/MaterialDependencies.ts`, on `aekasha`, p302 D6): an unregistered texture loads from `findTextureDeclaration` (the development data's texture section, else the first scene entry with the id, a streaming scene's cell assets included; a production build has only the scenes' entries, so a texture only code uses must be listed in a scene), in the caller's owner scope, and a registered one is re-tagged (`retagAssetOwner`). Their bodies, `loadSceneAssetsAsync(lists, ownerKey?)` and `createSceneObject3Ds(lists)` (returning the entity ids), also load a part of a scene's data: a streaming cell's assets in its owner key, every registration after the loads' awaits included, and its lights and meshes (p353 Phase 3). The glTF import path (`kernel/assets/import/ImportRegistry.ts`) loads with an `import()` only for a scene whose data names an imported asset, by id or inline (p613 D4), and hands `SceneAssetRelease.ts` its release on its first import (`setSceneImportRelease`), so a scene file's own `importAssetAsync` is released with its scene too. Work that needs the whole scene (the scene data's lights and meshes exist only after the scene code) waits with `runWhenSceneLoadSettled(run)` (`@internal`): `run` now, or once the running load has settled (a one-shot `loadSettled` hook; the settled hooks walk a copy, so one can remove itself), such as an instance set's pre-warm (p354 Phase 5 step 6).

Asset ownership (`kernel/assets/AssetOwners.ts`, `@internal`; owner sets since p353 Phase 2): each registered asset has a set of owner keys, a scene id or a streaming cell's `sceneId#cellKey` (`getCellOwnerKey`). A registration takes the current owner, the owner scope's (`runInAssetOwnerScope`, synchronous, so it ends at an `await`) or else the loading or current scene; a cache hit adds it (`retagAssetOwner`). An async loader captures the scope at its call (`getAssetOwnerScope`) and registers in it after its awaits: `loadTextureAsync` (arrays and atlas slots too), `buildTextureArray` and `importAssetAsync` (its geometries, textures and record), so a new async loader that registers does the same. `SceneAssetRelease.ts` frees an asset only once the released owners held it alone and nothing uses it: `releaseSceneOwnedAssets(sceneId)` takes the scene's key and its cells', `releaseCellOwnedAssets(sceneId, cellKey)` one cell's (not logged); an asset others hold too only loses the released keys, and one still in use keeps them for their next release. The Assets tab shows every owner; the GPU memory tab lists an asset several cells of one scene hold under the scene (`getMemoryOwner`).

Next to `?isDebug=true` or `?isProdTest=true` (the root `CLAUDE.md`'s Commands), `?startScene=<sceneId>` (`getStartSceneQueryParam`; null outside those two modes, so a production build never reads it) picks the first scene: `loadScene`'s first load (`kernel/scene/SceneLoader.ts`) uses it over the Debug tools' start scene and `src/index.ts`'s, with the scene code from the data's `sceneFiles` (`getAppData()`, the generated `sceneFileObjects`). An id without both its scene data and its scene file warns (also as a debug toast, queued by `addDebugToastWhenReady` until the toaster exists) and loads the usual start scene. Later loads ignore it; the debugger's scene loader still applies only while the Debug tools' start scene is on.
