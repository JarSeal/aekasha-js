Notes for the Smallest Build Possible (`devTools/sbp/`, `devTools/sbp.ts`, `sbp.config.ts`; p611): the report, the profiles and budgets, and the embed profiles; the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Smallest build possible

- `yarn sbp [--profile <id>[,<id>…] | all] [--no-build | --no-app-build] [--why <group | module path>] [--json] [--brief]` (`devTools/sbp.ts`): builds the profiles on one production gather (`appBuild.ts`' `buildBundles`: the app as `yarn build`'s bundle steps, an embed as `vite build` with `AEK_EMBED_PROFILE=<id>`), then reports per profile: the initial / lazy split (`bundleSplit.ts`: initial is the entry chunk, its manifest `imports` transitively and their CSS; everything else, workers and `?url` files included, is lazy), each group's size (`bundleModel.ts`' `getModuleGroup`: a package, each `_engine/kernel/<area>` and `_engine/features/<name>`, each other engine folder (`_engine/ui`, `_engine/utils`, …), `app`, `toolkit`, `vite`, `other`; its modules minified, gzipped together per chunk: see the module sizes below), the feature view with each feature's "why" (`bundleWhy.ts`: the shortest static import chain from the entry, through shipping modules first) and the scenes whose data needs it (`__features`), the diff against the committed baseline (`bundle.json`, an embed's `bundle.<id>.json`; printed, never failing: `verify:baselines` owns them), and the budgets. Exit 1 on a budget failure (any profile), 2 on an error; `--why` and `--json` take one profile. `--no-build` measures the last builds, `--no-app-build` the app's last and builds the embeds: `yarn build` runs `yarn sbp --profile all --no-app-build --brief` after its dev gather and before the Hub. `AEK_SBP=false` prints one line and exits 0 (`yarn build:test` doesn't run it: a debug build would fail the budgets). Output: `.cache/sbp/progress.log` (emptied per run) and `.cache/sbp/report.json` (`SBP_REPORT_FILE`, `REPORT_FORMAT_VERSION`, a key per profile, a run keeps the others; the Hub's `{{sbp:…}}` reads it, so bump the format when its shape changes, `devTools/hub/sbp.ts`). Sizes print in KiB written "kB" (`formatKB`, shared with `verify:baselines`); the Hub writes "KiB".
- The module sizes (`moduleSizesPlugin.ts`, p619 B1, V7): `vite.config.ts` puts `createModuleSizesPlugins`' `plugin()` in `plugins` and its `workerPlugin()` in `worker.plugins`, one collector for the main build and its worker builds. In `generateBundle` (the final file names) each module's rendered code is minified with esbuild (the build's target, no tree-shaking: a fragment's declarations are used by the chunk's other modules; a parse error counts it unminified, with a warning), each group's minified code is gzipped together per chunk, and each module's alone. The main build's `writeBundle` writes `dist-stats/module-sizes.json` (`ModuleSizesFile`: each chunk's build and groups, each module's build and size per chunk; an embed's `dist-stats/embed-<id>/module-sizes.json`). A worker build is named by its entry chunk (`PhysicsWorker`); a file a worker and the main build both emit (the same code: Rapier, the meshopt modules) is the main build's. About 1-2 s per app build. Groups compress apart, so they add up to a little more than a chunk (about 3 % for the app; the visualizer's unminified sizes summed to more than twice the download). `collectBundle` throws without the file or with one from another build (`BuildLocation.sizesFile`). The visualizer stays for the import graph (`--why`), the emitted files' importers and the treemap.
- The keys (`bundleKeys.ts`' `keyBuildFiles`, p619 B2): a file's key in `bundle.json`, the report and the budgets is its name without the hash (`assets/index.js`). Where two files share one, the manifest's file (a chunk, its CSS or assets) keeps it, a worker build's copy is `<key>@<worker>` (`assets/EngineRapier.js@PhysicsWorker`; a worker's files are its chunks in the module sizes and what they name, `findReachableFiles`), and two manifest files are `<key>@<source folder>` (`assets/draco_decoder.wasm@draco` / `@gltf`). Anything else throws (a file outside the manifest that no worker or two reach, two equal keys): the old `#2` numbering in hash order swapped two files' keys between builds. A `?worker` wrapper keeps the plain key (`assets/PhysicsWorker.js`, 0.1 kB); the worker's own file is `assets/PhysicsWorker.js@PhysicsWorker`.
- Profiles (`sbp.config.ts` at the repo root, `SbpProfile` and `checkSbpProfiles` in `config.ts`): `{ id, entry, scenes?, budgets? }`. `entry: 'src/index.html'` is the template app (`scenes` omitted: all); any other entry is an embed: a `.ts` module under `src/`, `scenes` required (no scene twice), the first the mount's default. Today: `app` and `banner` (`src/app/profiles/banner/`).
- Budgets (`SbpBudgets`, gzip bytes written `n * KIB`, in `config.ts`; checked by `budgets.ts`): `initial` (the report's `initial.total`), `chunks` (a `bundle.json` key, or an embed's root entry; a key without its file fails as `missing`), `groups` (a group's initial code; none is 0) and `modules` (a file or a folder ending in `/` under `src/`: its modules' own gzips in the initial chunks summed, a little over a group's; the built-in icons at 0). A `groups` key must name a group the report can have (an installed package, an engine folder, `app`, `toolkit`, `vite`, `other`) and a `modules` key a file or folder that exists: a typo measured 0 and always passed (p619 B3). A failed build's error is the one shown: the plugins' `closeBundle` does nothing after a failed build, and `buildBundles`' dev gather after a failed build is only reported. no `sbp/` module imports `verify/` (a test does) (the progress log is `devTools/progressLog.ts`, the growth tolerance `sbp/bundleGrowth.ts`). A budget is the size plus about 4%, at least 1 KiB, rounded up to a whole KiB (`suggestBudget`); "well under" (more than 10% and 2 KiB, `isWellUnderBudget`) is reported with the tighter value. The banner budgets every feature group at 0 (`FEATURE_GROUPS`, read from `src/_engine/features/`' folders, so a new feature is budgeted too): the floor's promise. Raise a budget only in the change that explains the growth.
- The production debug check (`verify/debugInProduction.ts`' `findDebugCodeInBuild`, run by `verify:baselines` on the app and every embed) reads its modules from the module sizes, the worker builds' included (a finding there names the worker), and also fails on a debug asset: an emitted file (`listEmittedAssets`, the manifest's entries that aren't chunks or CSS) whose source is in a debug folder or whose every importer is a debug module. Vite emits a `?url` file when it loads its importer, before tree-shaking, so a debug module's `?url` import is only kept out by an `import()` inside `if (__AEK_DEBUG__) { … }` or `__AEK_DEBUG__ ? … : null` (see `src/_engine/debug/CLAUDE.md`).
- The lite renderer (three's classic `WebGLRenderer`) was studied and not built (p611 §7): about 110 KiB less for the banner, for a second material path through every TSL area. Revisit when three ships its node system apart from `WebGPURenderer`, or an embed must be well under 200 KiB.

## Embed profiles

- Data (`devTools/gather/output.ts`, both gather modes): each embed profile gets `src/generated/profiles/<id>/` (`generatedAppData.json` with `{ scenes }` only, `generatedAppFns.ts` with its scenes' files and the TSL material and PostFX files those scenes list, `index.ts`), which its entry module imports. Any problem `checkSbpProfiles` finds in `sbp.config.ts` fails the gather (`yarn gatherAppData` and the dev server's too): a profile naming a scene the data doesn't have or a debug scene, and a budget key naming no group or no file; a folder no profile writes is removed. The app's `src/generated/` is unchanged by profiles.
- The entry (`src/app/profiles/<id>/<id>.embed.ts`, laid out as a scene folder, `layoutRules.ts`' `profiles/<id>/`): `mount(opts)` calls `mountAekasha` with the profile's data, its `features` and `assetBaseUrl: new URL('.', import.meta.url).href` in a build (`import.meta.env.DEV` leaves it out: the dev server serves the files from its root). The banner's is `features: []`, `renderer: { alpha: true, antialias: true }`, its mesh made in code (the camera, the light and the TSL material from its scene JSON; no loader).
- The build (`embedBuild.ts`, `vite.config.ts` merges `getEmbedBuildConfig` when `AEK_EMBED_PROFILE` is set): `dist-embed/<id>/` (gitignored), the entry at its root without a hash (`<id>.embed.js`: a facade re-exporting `mount` from the shared chunk `assets/<id>.embed.js`, since the scenes' chunks import the engine too), the rest hashed in `assets/`, `base: './'`, `publicDir: false`. Not Vite's library mode (it inlines every `new URL` file as base64 and doesn't minify ES output). `embedOutputsPlugin` prepends a `<link>` per CSS file of the entry and its static imports (Vite emits a JS entry's CSS but nothing links it), copies the files the profile's data names (`__url`s, `basis/` for a KTX2, `draco/` for imported assets; a missing one fails), then prunes: a crawl from the entry, its CSS and the copied files through the text files keeps every file a kept file names, and removes the rest (`.vite/aek-pruned.json`). That drops the physics worker and Rapier from a profile without physics; the assets worker, its jobs, the loaders and the decoders stay (kernel code names them; deployed, downloaded only when a scene uses them). `embedPaths.ts` holds the output paths apart from the plugin, which loads `sbp.config.ts` and the gather's output module, so the Hub and the verify commands read a build without it.
- Measuring: `collectBundle` with `getEmbedBuildLocation(id)` (every file of the folder but `.vite/`); `findMainChunkFile` takes the largest of the entry and its static imports. `verify:baselines` builds every embed after the app, diffs and records `bundle.<id>.json`, and runs the debug check on each.
- Checking it in a page: `yarn verify:embed` (`devTools/verify/CLAUDE.md`), whose banner run also loads the Hub's embed example (`devTools/verify/embedExample.html`). The Hub's `::: embed <profile>` runs a profile live (`hub/CLAUDE.md`); `yarn hub:build` copies its build into `_assets/embed/<id>/` (`devTools/hub/CLAUDE.md`).
- Limits (the Hub's embedding example lists them for app developers): the embed's files on the page's origin (module workers start only from it; a CDN would need blob workers), one engine per page load, no `SharedArrayBuffer` without COOP / COEP (physics' one message per frame), the dev server doesn't tree-shake (an embed it serves brings `page.scss`: check against a build), and the UI kit's `rem`s assume the template's 62.5% root font size (p617).
