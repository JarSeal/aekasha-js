Notes for the asset optimization pipeline (`devTools/assets.ts`, `devTools/assetPipeline/`; the how-to is `docs/techniques/asset-optimization.md`); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Asset pipeline

- `yarn build`: Its production gather fails when an asset a shipped scene uses has no asset pipeline output (`encoderMissing` or a failed encode) or is over its budget (`_DONE_p300` Phase 4: `budget` in `assets.config.json` / the asset's `optimize`, plus a per-texture ceiling from its profile's `maxSize` and codec; `devTools/assetPipeline/budgets.ts`). `AEK_ASSETS_ALLOW_UNOPTIMIZED=true yarn build` ships the ones without `ktx` unoptimized instead (`_DONE_p300` Phase 3 step 4). `dist/aek-assets/` gets only the outputs the production data loads (`devTools/assetOutputsBuildPlugin.ts`).
- `yarn setupAssetTools`: Installs the pinned `KTX_VERSION` (4.4.2; `ktxTool.ts`: Linux needs glibc ≥ 2.34, native Windows is refused, use WSL2). A no-op when a working `ktx` ≥ 4.4.0 exists (`AEK_KTX`, `.tools/`, PATH; 4.3 lacks options every encode passes). The pipeline runs the same setup itself before its first encode; a too-old or broken `ktx` is named in the log and the error, and in a long-running process (the dev server) a failed download isn't retried for 5 minutes. The install unpacks into a staging folder removed on any failure, and keeps a working copy another process set up meanwhile (`--force` replaces it). `ktx --version` gets 15 s and each `ktx create` 15 min, then is killed (a hung `ktx` would block the dev server's queue). Only needed to encode assets; `tsconfig.json` limits global `@types` to `node` (`types`): yarn 1 installs the deprecated stub `@types/wrap-ansi@8.1.0` for `@gltf-transform/cli`, and with our explicit `typeRoots` tsc fails on it (TS2688; `docs/issues/gltf-transform-cli-types-wrap-ansi-stub.md`).
- `yarn assets [--only <id|glob>]` — the asset optimization pipeline (`_DONE_p300`, `devTools/assets.ts` → `devTools/assetPipeline/`; the how-to is `docs/techniques/asset-optimization.md`): encodes every `*.texture.json`, `*.textureArray.json`, `*.textureAtlas.json` and `*.importedAsset.json` source, and each `*.mergeMaterial.json` palette's slot arrays (p374: a `textureArray` job per slot a member uses, keyed `mergeMaterial:<json>:<slot>`, built by `mergeMaterials.ts`' resolver; a palette whose class or layers fail is dropped, not pruned), into `src/public/aek-assets/` (KTX2 textures, arrays and atlas slots; meshopt GLBs), records each output in the committed `assets.lock.json` (unchanged assets are cache hits, so a clone needs no `ktx`), then gathers the generated data with their `__url`s. Only a full run without `AEK_ASSETS_OPTIMIZE` that has an output for every asset (no failure, no missing `ktx`, no asset JSON left out) deletes stale outputs and lock entries: `yarn gatherAppData` and the dev server run the same cached pipeline (`devTools/assetPipeline/command.ts`) but never prune, so run `yarn assets` before committing assets. More: `devTools/assetPipeline/CLAUDE.md`.
- `yarn assets`: `--only` builds the assets whose id matches, or whose JSON or source path from the repo root matches the glob; the others are only looked up. It exits 1 when an asset failed or is over its budget (the dev server only warns). Its prune (`getPruneBlockers`, `command.ts`) runs only when every asset has its output and no asset JSON or use was left out (`readAssetJsons` and `collectPipelineAssets` return their `dropped`); it skips a running process's `*.<pid>.tmp` and files changed since the run started, and it and every lock write hold `runLock.ts`' `.cache/asset-pipeline/run.lock` (`O_EXCL`, taken over when its pid is gone; a waiter gives up after 30 s with an error naming the file). Run stats go to `.cache/asset-pipeline/last-run.json`. Keys are memoized across processes in `.cache/asset-pipeline/key-memo.json` (`saveKeyMemo`, at a run's end: a key by its inputs and its files' size, mtime, ctime and inode, so a run doesn't re-hash an unchanged source); the key itself still hashes the source bytes, so the memo never changes a key. The walk for asset JSONs skips `src/generated/` and `src/public/aek-assets/` (`listSourceFiles`, `devTools/files.ts`). `fixtures/` holds the test scenes' fixture generators, run by hand (`assetCompareVariants.ts` for `assetCompare`, `textureArraysFiles.ts` for `textureArrays`, `mergeKitFile.ts` for `testDebugScene`'s `p371MergeKit.glb`, `textureSetsFiles.ts` for `textureSets`' hand-made `p303TestSet`, whose texture JSONs pass their PNGs through with `optimize: false`), not pipeline code. `--only`'s glob matches paths only: an id matches whole (`--only 'p303TestSet*'` matches nothing, `--only 'src/app/scenes/textureSets/**'` the set's textures). A clean encode isn't byte for byte the same on every machine: three of the repo's outputs (each with a resized source) encode to other bytes here than the lock's, with the same `ktx` and sharp, so compare outputs on one machine; `images.test.ts`' golden hash covers the pipeline's own image maths (resize, mip levels, alpha coverage) and needs a `PIPELINE_VERSION` bump with it. `optimize.alphaCoverage` (`_DONE_p341`, a `*.texture.json`'s or an atlas slot's own, the material's `alphaTest`) scales each mip level's alpha to level 0's coverage at that cut (`devTools/assetPipeline/alphaCoverage.ts`; bump `ALPHA_COVERAGE_VERSION` when what it writes changes); such a texture's levels are the pipeline's box chain, not `ktx --generate-mipmap`. At runtime, `loadTextureAsync` / `importAssetAsync` load an asset's `__url` instead of its `fileName` (`resolveAssetUrl`, `kernel/assets/AssetUrl.ts`; in dev data, `__sourceUrl` with a warning when the pipeline has no output).
- A GLB's `merge` (p371 D3; the how-to is `docs/techniques/asset-optimization.md`'s Merging pieces): `encodeGLTFAsset` (`gltf.ts`) runs `mergeGLTFNodes` (`gltfMerge.ts`) first, before the compression and the `lodChain` step, so a chain is built from the merged mesh. Not gltf-transform's `flatten` + `join`: `flatten` moves every node to the scene root (the runtime's import root and the kept nodes' transforms and paths would change), `join` keeps the first piece's node and transform, and its `transformPrimitive` writes tangents wrong and never negates a mirrored piece's `w`. The step copies each piece's primitives (`compactPrimitive`), dequantizes them, bakes the piece's transform into the import root's space with `GeometryMergeCore.ts`' maths (normal matrix; winding and tangent `w` flipped for a negative determinant) and joins them (`joinPrimitives`) into a new child of the import root with no transform: `__merged` (`ALL`) or `__merged_<material>` (`BY_MATERIAL`, always, GLTFLoader's sanitizing), `_2`, `_3`, … for pieces of another attribute set, a suffix for a name the file uses. Kept with their subtrees: `exclude` globs, physics nodes (`isPhysObj` / `colliderType` in the node's or its mesh's extras), joints, animated nodes; kept alone with a warning: skinned, GPU-instanced, morph-target and non-triangle ones. An emptied piece node and the parent it leaves childless are removed; the file's own empty nodes stay. Only the JSON's own `merge` counts, for every use of the file (`assets.ts`); the resolved options and `GLTF_MERGE_VERSION` (`gltfMergeOptions.ts`, apart from the step so a key doesn't load gltf-transform: bump it when what the step writes changes) are in the cache key only when set (`cache.ts`). A file with `merge` is written even when both sides pass through (`optimize: false`, `AEK_ASSETS_OPTIMIZE=false`; `pipeline.ts`), with a warning. Its stats (`GLTFMergeStats`: each merged node's parts, vertices and triangles, the kept nodes by reason) go into the lock entry and `last-run.json`, and the run's line (`describeMerge`). Tests: `gltfMerge.test.ts`.
- `yarn fetchTextureSources [--only <setId>[,…]] [--force]` (p303 D5; `devTools/fetchTextureSources.ts`, the logic in `textureSources.ts`): a texture set folder is one with a `source.json` beside its `*.textureSet.json` (one set per folder; a `source.json` alone, or beside two sets, fails that set), anywhere under `src/toolkit/` or `src/app/`; a set without one is hand-made (`p303TestSet`) and skipped. `source.json` (`TextureSourceSchema`, strict): `provider` (`ambientCG` or `polyHaven`), `assetId`, `download` (`2K-JPG`; Poly Haven's `2k` / `jpg`), `license`, `page`, `maps` (`color` required; `normal`, `roughness`, `ao`, `height`, `metalness`, `arm`): ambientCG's file-name suffix in its zip (`_NormalGL`; the stem must end with it, `.jpg`/`.png` only, two matches fail), Poly Haven's map name in its files API (`nor_gl`, checked against its MD5). Downloads are cached in `.cache/texture-downloads/` (a cached zip that doesn't read is fetched once more; `readZip` in `archives.ts` checks every entry's CRC-32). A set's maps go to its gitignored `source/raw/<map>.<ext>` (`.gitignore`: `src/toolkit/textures/*/source/raw/`, `src/app/**/source/raw/`; a set whose raw folder git doesn't ignore fails), the folder's other files removed, with `.fetched.json` (the source and each file's SHA-256: an unchanged set is "up to date" without a download); nothing is written until every map is in hand. A missing `color`, `normal` or `roughness` fails the set; another missing map is logged as optional. Then `src/toolkit/textures/CREDITS.md` is written from the toolkit's sets when it changed (not while one's `source.json` is invalid). The run's lines also go to `.cache/texture-downloads/progress.log`; it exits 1 when a set failed. Tests: `textureSources.test.ts`, `archives.test.ts`' zip cases.
