Notes for the asset optimization pipeline (`devTools/assets.ts`, `devTools/assetPipeline/`; the how-to is `docs/techniques/asset-optimization.md`); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Asset pipeline

- `yarn build`: Its production gather fails when an asset a shipped scene uses has no asset pipeline output (`encoderMissing` or a failed encode) or is over its budget (`_DONE_p300` Phase 4: `budget` in `assets.config.json` / the asset's `optimize`, plus a per-texture ceiling from its profile's `maxSize` and codec; `devTools/assetPipeline/budgets.ts`). `AEK_ASSETS_ALLOW_UNOPTIMIZED=true yarn build` ships the ones without `ktx` unoptimized instead (`_DONE_p300` Phase 3 step 4). `dist/aek-assets/` gets only the outputs the production data loads (`devTools/assetOutputsBuildPlugin.ts`).
- `yarn setupAssetTools`: A no-op when a working `ktx` ≥ 4.4.0 exists (`AEK_KTX`, `.tools/`, PATH; 4.3 lacks options every encode passes). The pipeline runs the same setup itself before its first encode; a too-old or broken `ktx` is named in the log and the error, and in a long-running process (the dev server) a failed download isn't retried for 5 minutes. The install unpacks into a staging folder removed on any failure, and keeps a working copy another process set up meanwhile (`--force` replaces it). `ktx --version` gets 15 s and each `ktx create` 15 min, then is killed (a hung `ktx` would block the dev server's queue). Only needed to encode assets; `tsconfig.json` limits global `@types` to `node` (`types`): yarn 1 installs the deprecated stub `@types/wrap-ansi@8.1.0` for `@gltf-transform/cli`, and with our explicit `typeRoots` tsc fails on it (TS2688; `docs/issues/gltf-transform-cli-types-wrap-ansi-stub.md`).
- `yarn assets`: `--only` builds the assets whose id matches, or whose JSON or source path from the repo root matches the glob; the others are only looked up. It exits 1 when an asset failed or is over its budget (the dev server only warns). Its prune (`getPruneBlockers`, `command.ts`) runs only when every asset has its output and no asset JSON or use was left out (`readAssetJsons` and `collectPipelineAssets` return their `dropped`); it skips a running process's `*.<pid>.tmp` and files changed since the run started, and it and every lock write hold `runLock.ts`' `.cache/asset-pipeline/run.lock` (`O_EXCL`, taken over when its pid is gone). Run stats go to `.cache/asset-pipeline/last-run.json`. `optimize.alphaCoverage` (`_DONE_p341`, a `*.texture.json`'s or an atlas slot's own, the material's `alphaTest`) scales each mip level's alpha to level 0's coverage at that cut (`devTools/assetPipeline/alphaCoverage.ts`; bump `ALPHA_COVERAGE_VERSION` when what it writes changes); such a texture's levels are the pipeline's box chain, not `ktx --generate-mipmap`. At runtime, `loadTextureAsync` / `importAssetAsync` load an asset's `__url` instead of its `fileName` (`resolveAssetUrl`, `kernel/assets/AssetUrl.ts`; in dev data, `__sourceUrl` with a warning when the pipeline has no output).
