Notes for the asset optimization pipeline (`devTools/assets.ts`, `devTools/assetPipeline/`; the how-to is `docs/techniques/asset-optimization.md`, and a texture set's recipes, cavity AO and KTX2 slots `docs/techniques/texture-sets.md`); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Asset pipeline

- `yarn build`: Its production gather fails when an asset a shipped scene uses has no asset pipeline output (`encoderMissing` or a failed encode) or is over its budget (p300 Phase 4: `budget` in `assets.config.json` / the asset's `optimize`, plus a per-texture ceiling from its profile's `maxSize` and codec; `devTools/assetPipeline/budgets.ts`). `AEK_ASSETS_ALLOW_UNOPTIMIZED=true yarn build` ships the ones without `ktx` unoptimized instead (p300 Phase 3 step 4). `dist/aek-assets/` gets only the outputs the production data loads (`devTools/assetOutputsBuildPlugin.ts`' `collectUrls`, which an embed profile's copy in `devTools/sbp/embedBuild.ts` uses too: every `__url` and a font's `__atlasUrl`, `OUTPUT_URL_KEYS`; p391 found a build dropping the atlas, named only inside the layout, before the data had its URL).
- `yarn setupAssetTools`: Installs the pinned `KTX_VERSION` (4.4.2; `ktxTool.ts`: Linux needs glibc ≥ 2.34, native Windows is refused, use WSL2). A no-op when a working `ktx` ≥ 4.4.0 exists (`AEK_KTX`, `.tools/`, PATH; 4.3 lacks options every encode passes). The pipeline runs the same setup itself before its first encode; a too-old or broken `ktx` is named in the log and the error, and in a long-running process (the dev server) a failed download isn't retried for 5 minutes. The install unpacks into a staging folder removed on any failure, and keeps a working copy another process set up meanwhile (`--force` replaces it). `ktx --version` gets 15 s and each `ktx create` 15 min, then is killed (a hung `ktx` would block the dev server's queue). Only needed to encode assets; `tsconfig.json` limits global `@types` to `node` (`types`): yarn 1 installs the deprecated stub `@types/wrap-ansi@8.1.0` for `@gltf-transform/cli`, and with our explicit `typeRoots` tsc fails on it (TS2688; `docs/issues/i260_gltf-transform-cli-types-wrap-ansi-stub.md`).
- `yarn assets [--only <id|glob>]` — the asset optimization pipeline (p300, `devTools/assets.ts` → `devTools/assetPipeline/`; the how-to is `docs/techniques/asset-optimization.md`): encodes every `*.texture.json` (but a `sourceOnly` one, p309 D1: an atlas cell's or array layer's source, encoded only by them; `collectPipelineAssets` skips it, the gather leaves it out of the development data's `textures` and fails a scene, a material or a texture set slot naming it, `getSourceOnlyTextureError`; tests: `assets.test.ts`, `gather.test.ts`' p309 block), `*.textureArray.json`, `*.textureAtlas.json`, `*.font.json` (p391: a distance field atlas and its layout, below) and `*.importedAsset.json` source, and each `*.mergeMaterial.json` palette's slot arrays (p374: a `textureArray` job per slot a member uses, keyed `mergeMaterial:<json>:<slot>`, built by `mergeMaterials.ts`' resolver; a palette whose class or layers fail is dropped, not pruned), into `src/public/aek-assets/` (KTX2 textures, arrays and atlas slots; meshopt GLBs), records each output in the committed `assets.lock.json` (unchanged assets are cache hits, so a clone needs no `ktx`), then gathers the generated data with their `__url`s. Only a full run without `AEK_ASSETS_OPTIMIZE` that has an output for every asset (no failure, no missing `ktx`, no asset JSON left out) deletes stale outputs and lock entries: `yarn gatherAppData` and the dev server run the same cached pipeline (`devTools/assetPipeline/command.ts`) but never prune, so run `yarn assets` before committing assets. More: `devTools/assetPipeline/CLAUDE.md`.
- `yarn assets`: `--only` builds the assets whose id matches, or whose JSON or source path from the repo root matches the glob; the others are only looked up. It exits 1 when an asset failed or is over its budget (the dev server only warns). Its prune (`getPruneBlockers`, `command.ts`) runs only when every asset has its output and no asset JSON or use was left out (`readAssetJsons` and `collectPipelineAssets` return their `dropped`); it skips a running process's `*.<pid>.tmp` and files changed since the run started, and it and every lock write hold `runLock.ts`' `.cache/asset-pipeline/run.lock` (`O_EXCL`, taken over when its pid is gone; a waiter gives up after 30 s with an error naming the file). Run stats go to `.cache/asset-pipeline/last-run.json`. Keys are memoized across processes in `.cache/asset-pipeline/key-memo.json` (`saveKeyMemo`, at a run's end: a key by its inputs and its files' size, mtime, ctime and inode, so a run doesn't re-hash an unchanged source); the key itself still hashes the source bytes, so the memo never changes a key. The walk for asset JSONs skips `src/generated/` and `src/public/aek-assets/` (`listSourceFiles`, `devTools/files.ts`). `fixtures/` holds the test scenes' fixture generators, run by hand (`assetCompareVariants.ts` for `assetCompare`, `textureArraysFiles.ts` for `textureArrays`, `mergeKitFile.ts` for `testDebugScene`'s `p371MergeKit.glb`, `textureSetsFiles.ts` for `textureSets`' hand-made `p303TestSet`, whose texture JSONs pass their PNGs through with `optimize: false`), not pipeline code. `--only`'s glob matches paths only: an id matches whole (`--only 'p303TestSet*'` matches nothing, `--only 'src/app/scenes/textureSets/**'` the set's textures). A clean encode isn't byte for byte the same on every machine: three of the repo's outputs (each with a resized source) encode to other bytes here than the lock's, with the same `ktx` and sharp, so compare outputs on one machine; `images.test.ts`' golden hash covers the pipeline's own image maths (resize, mip levels, alpha coverage) and needs a `PIPELINE_VERSION` bump with it. `optimize.alphaCoverage` (p341, a `*.texture.json`'s or an atlas slot's own, the material's `alphaTest`) scales each mip level's alpha to level 0's coverage at that cut (`devTools/assetPipeline/alphaCoverage.ts`; bump `ALPHA_COVERAGE_VERSION` when what it writes changes); such a texture's levels are the pipeline's box chain, not `ktx --generate-mipmap`. At runtime, `loadTextureAsync` / `importAssetAsync` load an asset's `__url` instead of its `fileName` (`resolveAssetUrl`, `kernel/assets/AssetUrl.ts`; in dev data, `__sourceUrl` with a warning when the pipeline has no output).
- A GLB's `merge` (p371 D3; the how-to is `docs/techniques/asset-optimization.md`'s Merging pieces): `encodeGLTFAsset` (`gltf.ts`) runs `mergeGLTFNodes` (`gltfMerge.ts`) first, before the compression and the `lodChain` step, so a chain is built from the merged mesh. Not gltf-transform's `flatten` + `join`: `flatten` moves every node to the scene root (the runtime's import root and the kept nodes' transforms and paths would change), `join` keeps the first piece's node and transform, and its `transformPrimitive` writes tangents wrong and never negates a mirrored piece's `w`. The step copies each piece's primitives (`compactPrimitive`), dequantizes them, bakes the piece's transform into the import root's space with `GeometryMergeCore.ts`' maths (normal matrix; winding and tangent `w` flipped for a negative determinant) and joins them (`joinPrimitives`) into a new child of the import root with no transform: `__merged` (`ALL`) or `__merged_<material>` (`BY_MATERIAL`, always, GLTFLoader's sanitizing), `_2`, `_3`, … for pieces of another attribute set, a suffix for a name the file uses. Kept with their subtrees: `exclude` globs, physics nodes (`isPhysObj` / `colliderType` in the node's or its mesh's extras), joints, animated nodes; kept alone with a warning: skinned, GPU-instanced, morph-target and non-triangle ones. An emptied piece node and the parent it leaves childless are removed; the file's own empty nodes stay. Only the JSON's own `merge` counts, for every use of the file (`assets.ts`); the resolved options and `GLTF_MERGE_VERSION` (`gltfMergeOptions.ts`, apart from the step so a key doesn't load gltf-transform: bump it when what the step writes changes) are in the cache key only when set (`cache.ts`). A file with `merge` is written even when both sides pass through (`optimize: false`, `AEK_ASSETS_OPTIMIZE=false`; `pipeline.ts`), with a warning. Its stats (`GLTFMergeStats`: each merged node's parts, vertices and triangles, the kept nodes by reason) go into the lock entry and `last-run.json`, and the run's line (`describeMerge`). Tests: `gltfMerge.test.ts`.
- `yarn fetchTextureSources [--only <setId>[,…]] [--force] [--scaffold]` (p303 D5; `devTools/fetchTextureSources.ts`, the logic in `textureSources.ts`): a texture set folder is one with a `source.json` beside its `*.textureSet.json` (one set per folder; beside two sets fails that set), anywhere under `src/toolkit/` or `src/app/`; a set without one is hand-made (`p303TestSet`) and skipped. A `source.json` without a set is a source folder (p309 D1: a decal's maps, which its pack recipes put into an atlas cell, `src/toolkit/textures/decalsGround/<decal>/`): fetched the same way, its id the folder's name (`--only`, the credits; an id two folders have fails both), `--scaffold` skips it. `source.json` (`TextureSourceSchema`, strict): `provider` (`ambientCG` or `polyHaven`), `assetId`, `download` (`2K-JPG`; Poly Haven's `2k` / `jpg`), `license`, `page`, `maps` (`color` required; `normal`, `roughness`, `ao`, `height`, `metalness`, `arm`, `opacity`): ambientCG's file-name suffix in its zip (`_NormalGL`; the stem must end with it, `.jpg`/`.png` only, two matches fail), Poly Haven's map name in its files API (`nor_gl`, checked against its MD5). Downloads are cached in `.cache/texture-downloads/` (a cached zip that doesn't read is fetched once more; `readZip` in `archives.ts` checks every entry's CRC-32). A set's maps go to its gitignored `source/raw/<map>.<ext>` (`.gitignore`: `src/toolkit/textures/**/source/raw/`, `src/app/**/source/raw/`; a set whose raw folder git doesn't ignore fails), the folder's other files removed, with `.fetched.json` (the source and each file's SHA-256: an unchanged set is "up to date" without a download); nothing is written until every map is in hand. A missing `color`, `normal` or `roughness` fails the set; another missing map is logged as optional. Then `src/toolkit/textures/CREDITS.md` is written from the toolkit's sets and source folders when it changed (not while one's `source.json` is invalid). The run's lines also go to `.cache/texture-downloads/progress.log`; it exits 1 when a set failed. `--scaffold` (p303 D3, `textureSetScaffold.ts`) first writes the texture JSONs the set's `packings` name and no file has (`<textureId>.texture.json` in the set folder; an id another `*.texture.json` gives is kept too), each a pack of D2's channel layout from `./source/raw/<map>.<ext>` (the `download`'s format): LITE `albedoRough` RGB colour × AO (`surface.aoStrength` as the multiply's strength), A roughness; `normalHeight` RG the normal (`normal: true`), B height (`remap: "auto"`); FULL `albedoHeight` (colour, height), `normal`, `orm` (AO or 1, roughness, metalness 0); MINIMAL `albedoHeight` (colour × AO, height); a missing height is 0.5; without an `ao` map the AO is the height's `cavity` (written out: `PACK_CAVITY_DEFAULTS`, the radius scaled from 2K by the `download`'s resolution), with neither no multiply and an `orm` R of 1; profile `terrainLayer` with the slots `baseColor` / `data` / `normal` / `orm`, `REPEAT`, anisotropy `MAX`, sRGB for the albedo slots; Prettier-formatted (`devFiles/format.ts`). It never overwrites a JSON: a written recipe is the set's to tune. It needs `normal` and `roughness` maps. Tests: `textureSources.test.ts` (source folders: p309), `textureSetScaffold.test.ts` (each recipe against `TextureAssetSchema`), `archives.test.ts`' zip cases.
- **A clone without the fetched sources** (p303 Phase 2 section 2): a file in a `source/raw/` folder is a fetched source (`isFetchedSourceFile`, `sources.ts`), gitignored. A pack that reads one records a `recipeKey` in its lock entry (`getRecipeKey`, `cache.ts`: its key with the fetched files' bytes left out, its params, the `src` paths among them, and its other files' bytes kept). When a fetched source is missing, the full key can't be made, so the pipeline (`lookUp`, `pipeline.ts`, both the encode and the pack pass-through) looks the recipe key up (`cache.getByRecipe`: through `get`, so the store's copy is restored and the prune keeps it) and takes that output as a hit; an edited recipe or a changed committed source finds none and fails: "no committed output has this recipe, and its fetched sources aren't there (…): run yarn fetchTextureSources". `resolvePackFile`'s `allowUnfetched` returns a missing fetched source's path (the key's file list, the gather's `checkPackSources`), and its error otherwise names the command. An entry gets a `recipeKey` only when its pack reads a fetched source, so no other lock entry changed. Not covered: a build-time `*.textureArray.json` whose layers are such packs (its key reads them; p303's arrays are runtime, Phase 3). Tests: `fetchedSources.test.ts` (temp root: the recorded key, the clone's hit kept by the prune, an edited recipe and a changed committed source failing, a missing committed source failing as before).
- **Cavity AO** (p303 D2, `pack.ts`): a pack channel's or a `multiply` factor's `cavity: { radius?, strength? }` (`PackCavitySchema`) makes D2's AO term from a height channel, `1 − strength × max(0, blur(h) − h)`, `h` remapped to 0..1 first, after `remap` / `invert`, before `multiply`, clamped; the blur (`blurWrapped`) is a Gaussian of sigma `radius` px at the pack size as three box passes each way, wrapping at the edges. Defaults `PACK_CAVITY_DEFAULTS` (24, 4): fitted to ambientCG Ground080's 2K scan against its own AO (mean 0.91 vs 0.88, correlation 0.76; sigma 8 gave 0.67). The strength suits a ground scan only, and the scaffold writes it for every set: a height map with narrow deep pits clamps to black at 4 (ice: 2 % of `ice01`'s texels), where scanned AO maps never reach 0, so the toolkit's ice sets use 1 and `concrete01` 2 (p303 Phase 4, matched to the AO maps' 1st percentile). A pack that uses one has `PACK_CAVITY_VERSION` in its key (`getPackKeyParams`, every pack key: the encode, the pass-through, an array's layer), so only those encode again when it's bumped; the other packs' keys didn't change. Tests: `pack.test.ts`.
- **Cube textures** (p311 D1-D3; `textureCubes.ts`, beside `textureArrays.ts` and `textureAtlases.ts`): a `*.texture.json`'s `faces` (six sources in the order +x, −x, +y, −y, +z, −z, each what `fileName` takes, `path` applying to public ones) in place of `fileName` and `pack` (`TextureAssetSchema`'s `superRefine` refuses two of the three, and with `faces` any `texOpts.flipY` and `optimize.alphaCoverage`; `InlineTextureSchema` omits from the unrefined `TextureAssetObjectSchema`, so an inline texture has no `faces`). `resolveCubeSource` resolves each face through `textureArrays.ts`' `resolveFileLayer` (an error per face, `faces[4] (+z): …`), `listCubeFiles` gives the key's files in face order, and `encodeCubeTexture` checks the faces square and of one size (else an error naming the face), fits them to `maxSize` (default 1024: a 1024 cube's PMREM is 67 MB on the GPU, a 2048 one's 268 MB) and writes one KTX2 cube, RGBA when a face has alpha, its faces stored as they are (not flipped): `ktxEncode.ts`' `encodeKtx2Cube` / `getKtxCubeArgs` (`getKtxCreateArgs`, then `--cubemap`; mips by the encoder). Output `aek-assets/<json path>.cube.<hash>.ktx2` (`getCubeLogicalPath`); the pipeline key is `texture:<json>:cube:<json>:srgb|linear` (`getPipelineAssetKey`), never `:unflipped`, whatever a scene entry's `texOpts` says; the key params `kind: 'cubeTexture'`, the slot, the settings, `isSrgb`, the output. D3: `settings.ts`' built-in `CUBE_LEVEL` (`textures.default.codec: 'etc1s'`, on input `isCubeSource`) is applied after the profile, like the collider default, so only the JSON's own `optimize.textures` names another codec (not a rule's, a profile's or `assets.config.json`'s `defaults`, which say `uastc`; the budget's ceiling uses it too): Phase 0 measured a 2048 UASTC + zstd cube at ~1.1 s to load against ETC1S's ~128 ms, at 6.5× its bytes. Codec `none` throws ("a cube texture is a KTX2 file", `getTextureArraySlotSettings`, also the gather's `checkCubeSources`); with the textures side off a cube is `skipped`, no output, like an array. `EncodedTexture.isCube`: the VRAM figures and the budget count six faces (`getTextureImageCount`, `generated.ts`). Production: `isKtxOnlyAsset` includes a cube, so one without an output fails the build, and `AEK_ASSETS_ALLOW_UNOPTIMIZED` doesn't ship it unoptimized. The development data has its faces' URLs as `__sourceUrls` (written even without a run) for the runtime's six-image fallback; the gather side and the sky box's use are in `devTools/gather/CLAUDE.md` and `src/_engine/features/skybox/CLAUDE.md`. An array layer or atlas cell naming a cube texture stays refused (`textureArrays.ts`' check reads `faces`). Tests: `textureCubes.test.ts`, `ktxEncode.test.ts`, `settings.test.ts`, `assets.test.ts`, `TextureSchema.test.ts`. The app's example is scene01's `desertDunes` (six 2048 PNGs, 22.6 MB → 637.5 KB at 1024, 9.4 s).
- **Quantized meshes** (i020; `gltfQuantization.ts`): `compressGeometry` (`gltf.ts`) runs `meshopt()` and `quantize()` through `quantizeRecordedAsync`, which computes each mesh's quantization volume before the transform (gltf-transform 4.5.1's `getPositionQuantizationVolume` and `getNodeTransform`, not exported: re-check them on a gltf-transform update; `gltfQuantization.test.ts` compares the record with the encoded matrices) and records it after, in the extras of every node using the mesh (`aekQuantization`: `GLTFQuantizationExtras` in the import-free `src/_engine/kernel/assets/import/GLTFQuantization.ts`, `offset`, `scale`, `version` and where `quantize()` put it: `NODE` its matrix, `PIVOT` a new child it moved the mesh into because the node has children or is animated, `INSTANCES` the GPU instances' matrices). Not recorded: a skinned node, a source already quantized, GPU instances without TRS (a warning: `quantize()` drops their dequantization). The import makes the positions floats again (`GLTFExtract.ts`), so `getGeometryBytes` counts them as floats (`listDequantizedPositions`, their LOD levels' too), and the budgets see the VRAM the import uploads. The LOD chain step reads a pivot's parent's extras (`getSourceNode`). `GLTF_QUANTIZATION_FORMAT_VERSION` is in a quantizing encode's key only (meshopt or `none` with `quantize`; not Draco, whose decoder makes floats): bump it when the record's format changes.
- **Fonts** (p391; the how-to is `docs/techniques/text-fonts.md`, the asset and the runtime `src/_engine/features/text/CLAUDE.md`): `devTools/assetPipeline/fonts/`, `import()`ed by `pipeline.ts` on a font's first encode. D1's hybrid generator: **RGB from `msdfgen-wasm`** 1.0.0 (`msdfgen.ts`, its own types: the package's `exports` names none; loaded through `createRequire` of its CJS entry, whose ESM has extensionless imports Node can't load; its `.wasm` from `msdfgen-wasm/wasm`; `loadGlyphs` with `preprocess: true`, `computeGlpyhMsdfData` for each glyph's box and projection, `generateBitmap`; its rows are top first: it flips them), **A from our true SDF** (`trueSdf.ts`: fontkit's outline in the same projection, curves flattened to 1/100 px, the nearest segment's distance signed by non-zero winding, mapped like msdfgen's channels), **everything else from fontkit** 3.0.0 (`fontFile.ts`: the refusals by signature (WOFF2, a collection) and an `fvar` table (a variable font: msdfgen-wasm reads its default instance only), metrics, kerning through `font.layout` of each pair with `liga`, `clig`, `dlig`, `calt`, `rlig` off, a pair it still substitutes skipped; not opentype.js, whose state leaks between glyphs). `MSDF` writes alpha 255, `SDF` only the alpha (a one-channel atlas). `fontSource.ts` (light: no fontkit) resolves the JSON with `FONT_DEFAULTS`, its files and the key's params; `charset.ts` the requested characters (presets from the engine's import-free `FontCharsets.ts`, `chars`, `charsFromFiles`, the collected ones, space and the fallback; control characters dropped); `outline.ts` the overlap check (samples spread along each contour: a glyph whose contours overlap gets a too-small alpha inside near the overlap, warned naming the glyphs, not fixed); `pack.ts` a skyline packer (not `textureAtlases.ts`' layout, which aligns cells for mips), growing by powers of two to `atlas.maxSize` and failing past it naming how many fit; `layout.ts` builds the layout from **`src/_engine/features/text/FontLayoutFormat.ts`, the format's one definition** (imported and re-exported: a change there bumps `FONT_LAYOUT_FORMAT` and `FONT_ENCODER_VERSION`); `encodeFont.ts`' `generateFontAtlasAsync` (pixels and the layout's input, no `ktx`) and `encodeFontAsset` (then the KTX2 and both outputs). Outputs: `<json path under src/>.atlas.<hash>.ktx2` (`ktxEncode.ts`' `encodeKtx2Raw` / `getKtxRawArgs`: `--format R8G8B8A8_UNORM`, or `R8_UNORM` for `SDF`, `--assign-tf linear --assign-primaries none --zstd 19`, no mips) and `.layout.<hash>.json` beside it (`getFontLogicalPath`, `outputs.ts`). In the pipeline: one job per font keyed `font:<json>` (`getFontAssetKey`, `assets.ts`), its source kind `font`, key type `font` (the pipeline's, `ktx`'s, sharp's, fontkit's and msdfgen-wasm's versions, `FONT_ENCODER_VERSION`, the resolved JSON and the requested characters' hash: `getFontKeyParams`); the layout is the result's `output`, the atlas its `extraOutputs` (on `CacheEntry` and the optimized outcome: the presence check, the store, its restore and the prune see every output). A font is always encoded (no pass-through form, whatever the textures switch says) and `isKtxOnlyAsset` (a production build fails without its output, even with `AEK_ASSETS_ALLOW_UNOPTIMIZED`). **Collected characters** (D5): `collectPipelineAssets` reads the gather's `src/generated/fontCharsets.json` once (`readCollectedFontChars`; a file that doesn't read drops the collecting fonts from the run, no prune, naming it), `createFontSource` keeps `collected` only for a collecting font, and the key hashes them with the requested set (a collected character a preset already holds changes no key; a non-collecting font's key ignores the file). A `yarn assets` run reads the file the last gather wrote, so a scene changed since needs a second run. **Budgets** are warnings (`FONT_BUDGET`, `budgets.ts`: 2048² atlas pixels, 2000 glyphs; `getFontBudgetWarnings`), not the texture ceilings (a 2048² RGBA atlas would fail those). The run's line and `last-run.json` carry `FontEncodeStats` (type, glyphs, missing, kerning pairs, overlaps, atlas size). `yarn importFont` (`devTools/importFont.ts`, root `CLAUDE.md`'s Commands) plans the import (`planFontImport`, nothing written), writes it (`writeFontImportAsync`) and runs `yarn assets --only <id>` as a child process (`assets.ts` runs at import); an id another `*.font.json` has is refused. Dependencies: `msdfgen-wasm` 1.0.0, `fontkit` 3.0.0, `@types/fontkit` 2.0.9 (written for fontkit 2; it matches what's used), all pinned devDependencies. Tests: `fonts/*.test.ts` (the charsets, kerning, the layout's shape and rounding, the packer, the true SDF against the outline at 8×, the refusals; a golden `DIGITS` atlas of `src/toolkit/fonts/plexSans/`' font in `fixtures/plexSansDigits.golden.png` / `.json`, within 1 per channel, written again by `AEK_UPDATE_FONT_GOLDEN=true yarn test devTools/assetPipeline/fonts` with a `FONT_ENCODER_VERSION` bump), `importFont.test.ts` (in a temp `src/`), `cache.test.ts`' extra outputs, `ktxEncode.test.ts`' raw args.
- **Average colour** (p303 D1, `textures.ts`' `getAverageColor`): an sRGB standalone texture's encode records the mean of its stored level 0's RGB, linear, 4 decimals, as `EncodedTexture.averageColor` (so in its lock entry and a cache hit's result); an output encoded before it has none until it encodes again (the key didn't change). The development data gets it as the texture's `__averageColor` (`getGeneratedFields`, production never: it would cost every shipped texture bytes); the gather gives a texture set its default packing's colour slot's as `averageColor` (`devTools/gather/textureSets.ts`). Tests: `textures.test.ts`, the gather's "p303 D1: a set's average colour".
