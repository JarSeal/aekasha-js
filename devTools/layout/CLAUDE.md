## Layout check

- The layout check (`devTools/layout/`, p619 D9; p602's move map before p608 and p609 moved the files): `layoutRules.ts` holds the layout as rules (the folders of the Three-folder split below; a new folder gets a rule there), and `layout.test.ts` (in `yarn test`) checks the working tree against it: every engine, toolkit and app file under a rule, the engine's and toolkit's modules in PascalCase, no two paths differing only in case, and the imports through the entries (`importGraph.ts`): no engine → toolkit / app / generated import, no kernel runtime import of a feature (the assets worker's job `import()`s apart), no static `_dbg__` import outside debug code, the `utils/`, `schemas/` and `ui/` boundaries, no feature cycle. `npx tsx devTools/layout/layoutReport.ts` writes the whole picture, the allowed type-only imports by file and line included, to `.cache/layout/layoutReport.md` (not committed).
- `npx tsx devTools/layout/migrateToEntries.ts [--check] <folder | file>...` — p606's codemod (`entryImports.ts` holds its rules, tested): rewrites deep engine and toolkit imports in the given folders and files to entry imports, each name to the entry that exports it, one value import and one `import type` per entry, Prettier-formatted. Leaves engine code, imports within a toolkit category and `*.tsl.ts` imports alone. Any error (a name in no entry or in two, a namespace / default / side-effect / dynamic import, `export *`, an unresolved path) is listed and nothing is written; `--check` exits 1 when a module would change. It ships with the engine major for apps made from the template (the Hub's migration guide).
