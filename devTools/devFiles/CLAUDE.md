Notes for the dev file server (`devTools/devFilesPlugin.ts`, `devTools/devFiles/`, the client `src/_engine/debug/_dbg__DevFiles.ts`); the root `.claude/CLAUDE.md` keeps the project-wide rules, commands and workflow.

## Dev files

- Dev files (`_DONE_p342`; public API `debug/DevFiles.ts` → `debug/_dbg__DevFiles.ts`, server `devTools/devFilesPlugin.ts` + `devTools/devFiles/`, the shared protocol `debug/DevFilesProtocol.ts`, which has no imports so Node loads it too): debug tooling writes files into the repo while `yarn dev` runs, through routes under `/__aek/files/` (`status`, `read`, `stage`, `commit`) of a dev-only Vite plugin (never in a build). A write is an ordinary file event, so the gatherer and the asset pipeline run as for an editor save and the page reloads after the gather.
  - API: `getDevFilesStatus()` (never rejects: `{ available, reason?, server }`), `writeDevFiles(writes)` (all or nothing; a write is `{ path, json }`, `{ path, blob }` (staged first) or `{ path, saveData: { sceneId, entry } }`, each with an optional `expectedHash`: the hash `readDevFile` returned, or `null` for "must not exist yet"; resolves per file `created` / `updated` / `unchanged`, rejects with `DevFilesError` and its code), `readDevFile(path)` (`null` when missing), `encodePNG(source, { flipY? })` (byte-exact for `ImageData` / RGBA8 buffers: a transparent pixel keeps its colour, which a canvas loses) and `onDevDataGathered(fn)` (the `aek:gather` event; the reload waits up to 2 s for `fn`'s promise).
  - Security: a per-start token in `index.html` (`<meta name="aek-dev-files">`, sent as `X-Aek-Dev-Token`; `status` needs none), a `Host` check (`localhost`, `*.localhost`, a loopback IP (never a DNS name like `127.x.example`), the machine's addresses, `server.allowedHosts`; against DNS rebinding) and an `Origin` check, all in the plugin (Vite's own host check runs after `configureServer` middlewares; the Host and Origin check is `devTools/hostCheck.ts`, which the Hub's dev routes share). Writes from the server's machine only, unless `AEK_DEV_FILES_LAN=true`: a loopback socket without a proxy header (`Forwarded`, `X-Forwarded-For`, `X-Forwarded-Host`, `X-Real-IP`, `Via`), so a localhost tunnel (ngrok, VS Code's port forwarding) isn't local (`isLocalRequest`).
  - Paths: repo-relative inside `src/app/`, `src/toolkit/` or `src/public/` (never `src/public/aek-assets/`, `draco/`, `basis/`, nothing in `src/_engine/`, no dot segment, no `node_modules` segment, no symlink out, no tool config name: `package.json`, `tsconfig*.json`, `jsconfig*.json`, `DEV_FILES_DENIED_NAMES`), extensions `.json`, `.png`, `.jpg`, `.jpeg`, `.webp` (never code: Vite would run a written `.ts`; a staged image must start with its format's signature, else `INVALID_IMAGE`, `imageCheck.ts`), 32 MB per file and 128 MB per batch. A JSON is sent as a value: the server validates a gathered suffix against its schema (`validateGatheredJson`, `gather/gatheredJson.ts`) and formats it with Prettier and the repo root's `.prettierrc` only (`format.ts`: Prettier's own lookup from the target's folder would `require()` a config a write put there). A JSON over 32 MB is refused before Prettier formats it. A batch is written through temporaries and renames, with backups (the last 20 commits in `.cache/dev-files/backup/`) restoring every file on a failure; right before the renames each target is checked again against what the plan read (a save in between, an editor's, is `CONFLICT`, not overwritten); a file whose bytes don't change isn't written (no gather). Staged files expire after 10 minutes (`STAGE_EXPIRED`) and go in the server's own `.cache/dev-files/stage/<pid>-<id>/` (removed when it closes, or by a later server once that pid is gone), so two servers (`dev:https`, the self-check's) don't empty each other's. An unknown route is `BAD_REQUEST` (`NOT_FOUND` is a missing file, which `readDevFile` turns into `null`), and a read without its hash header gives the client a hash of zeros, so the write that uses it is a `CONFLICT`.
  - Save entries: a `saveData` write reads the asset JSON (a gathered type with `__saveData`, not texture arrays or atlases), puts `entry` first in `__saveData[sceneId]`, stamps `__meta` (`engineVersion`, `toolkitVersion`, `appVersion` from `package.json` on each write; `date` unless the entry has one) and keeps `getDevFilesSaveHistorySize()` entries for that scene. It replaces, it doesn't merge: the entry must carry everything the latest one had. `__saveData` is read by own keys (`toString` is a scene id like any other), and `__proto__` is refused. An entry equal to the latest is `unchanged`. The history size is `AppConfig.devFiles.saveHistorySize` (default 20; -1 all, 0 saving off: `SAVE_DATA_DISABLED`), overridden per browser in the Debug tools tab's "File server" folder (`debugToolsState.devFiles`, saved only once changed), and always 0 outside the debug env.
  - The "File server" folder also shows whether this page can write ("Dev files": on, LAN too, off, unavailable and why), asked on every mount of the tab.

Commands: Its self-check, `yarn verify:devFiles` (`devTools/devFiles/selfCheck.ts`, a plain tsx script; its lines also go to `.cache/verify/progress.log`), starts its own dev server on 8091 or the next free port (with `AEK_DEV_FILES_FAULTS=true`, for the forced rename failures), writes into `src/app/__devFilesSelfCheck__/` (its save entry scenes' scene file too, written directly) and removes it, and leaves `src/generated/` as it found it; `--url http://localhost:8080` runs it against a running `yarn dev` (without the forced failures; its page reloads on the self-check's gathers). Run it after a change to the plugin or `devTools/devFiles/`: no hook runs it. The unit tests: `security.test.ts` (the Host, Origin, loopback and proxy rules), `config.test.ts` (the root-only Prettier config, the denied config file names, the image signatures) and `commit.test.ts` (the re-check before the renames, the size limit before Prettier, a stage folder per server, a broken symlink folder, the `toString` / `__proto__` scene ids).
