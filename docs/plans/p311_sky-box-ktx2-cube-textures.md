# Sky Box KTX2 Cube Textures and Pre-filtered Environments — Plan

A `CUBE_TEXTURE` sky box base loads six images (`fileNames`, `layers/Base.ts`' `loadCubeTexture`,
through the engine's texture loader) and bakes its PMREM at runtime (`getPMREMTexture`,
`SkyEnvironment.ts`). three r187 makes two things possible that weren't on WebGPU:

- **KTX2 cube textures** (`CompressedCubeTexture`, #35083): before r187 a KTX2 cube rendered black
  on the WebGPU backend (uploaded as 1 × 1 × 6). With uncompressed data in compressed textures
  (#35082), UASTC-HDR or half-float KTX2 uploads on WebGPU too (an RGBA half fallback): an option
  for HDR skies, which load as uncompressed `.hdr` equirects today.
- **Pre-filtered environments:** `PMREMNode.updateBefore` uses a texture with `isPMREMTexture` as
  it is, and `updateFromTexture` reads a `CompressedCubeTexture`'s face mips, so a cube whose mips
  are already the PMREM's roughness levels skips the runtime bake (three's
  `webgl_materials_envmaps_fasthdr` example does this).

Not urgent: no sky box needs it today. It cuts a texture sky's download (six PNGs → one KTX2) and
its first-frame bake.

## Grounding (2026-11-05)

- `SkyBoxCubeBaseSchema` (`SkyBoxSchema.ts`): `fileNames` (six), `flipY`, `colorSpace`, `rotate`,
  `intensity`.
- `loadCubeTexture` sets `generateMipmaps = true`: wrong for a compressed cube (its mips come in
  the file, and a compressed format can't generate them).
- The asset pipeline (`devTools/assetPipeline/`, `yarn assets`) encodes 2D textures and texture
  arrays with KTX-Software's `ktx`; it skips cube textures (`textureArrays.ts`: "the texture is a
  cube texture"). `ktx create --cubemap` takes six faces.
- r187's PMREM is a `CubeRenderTarget` with only the prefiltered mips down to 8 texels, at least
  256 per face (p057 D1): a pre-filtered KTX2 has to match that layout and its roughness ramp
  (`PMREMGenerator.lodToRoughness`), or PMREMNode samples the wrong roughness per level.

## Design (to refine)

1. **A KTX2 cube base:** `fileName` (one `.ktx2`) as the alternative to `fileNames` in the cube
   base schema; the loader goes through the KTX2 path (the engine's `KTX2Loader` setup) and skips
   `generateMipmaps`; `flipY` and `rotate` as for six images.
2. **The pipeline encodes cubes:** a texture JSON whose `fileName` is six faces gets
   `optimize.ktx2`, encoded with `ktx create --cubemap` (ETC1S or UASTC, mips generated by the
   encoder), recorded in `assets.lock.json` like any output.
3. **Pre-filtered (optional, after 1-2):** a build step that bakes a cube's PMREM (in a headless
   browser, or `PMREMGenerator` against the WebGL backend) and writes its levels as a KTX2 cube,
   marked `isPMREMTexture` at load. Only if the runtime bake shows up in a scene's first frame
   (measure it in Phase 0).

## Phases

0. **Measure:** a texture sky's first-frame cost (the PMREM bake) and its download, six PNGs
   against one KTX2 cube, on WebGPU and WebGL2.
1. KTX2 cube bases (design 1), with an example sky box in the app.
2. The pipeline's cube encode (design 2).
3. Pre-filtered cubes (design 3), if Phase 0 says so.
4. Hub (the sky box page's base layer section, the asset pipeline page), `CLAUDE.md`s, versioning
   (an engine minor: new schema option).
